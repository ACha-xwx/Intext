# M2 边界案例 fixture

这些是人工判据，不是模型实测结果。

1. 未确认需求、候选、开放冲突、待复核需求或 `blocking_direction` 未知存在时，程序应在调用前拒绝。
2. 输出漏掉任一正式需求覆盖、引用输入外需求／步骤／交付物／完成标准，或形成步骤／关键工作循环依赖时，解析拒绝，旧方案保持不变。
3. 输入含 `can_defer` 未知时，输出必须按 `source_gap_id` 逐项保留；不得因模型遗漏而视为解决。
4. 用户编辑目标或步骤后，需求版本不变，方案版本递增，确认清除，受影响关键工作待复核。
5. 用户实际修改需求后旧方案保留为 `stale`；需求重新确认后重新生成，旧方案进入归档，新方案获得新 ID。
6. 返回期间任务、类别、需求版本、方案版本或连接配置变化时，旧返回拒收。
