## 1. 实现与入口

设置页“诊断”区域提供“开启 Debug 控制台”复选框。开启独立 Tk 窗口，支持全部日志及 INFO/WARN/ERROR/CRITICAL 阈值筛选、自动滚动、复制、清空显示和打开日志目录。关闭窗口取消开启偏好；正常应用退出保留偏好，下次启动恢复。

程序启动即写入 `%LOCALAPPDATA%/PromptSmith/logs/latest.log`，不依赖开关。UTF-8 日志包含毫秒时间、线程、级别和模块；单文件约 5 MiB，保留三个轮转备份。单条异常不截断，可能使文件超过阈值。控制台内存 1,500 条、显示约 6,000 行，历史通过文件查看；轮转并非无限留存。

覆盖 standard logging 五级日志、stdout/stderr、Python warnings、进程/线程/对象清理未捕获异常、Tk 回调、后台操作、UI 信息/警告/错误、API、模型校验证据和 Skill 搜索降级。完整 traceback 包含底层 cause；UI 导入在日志建立后进行，导入失败也可诊断。启动日志提供系统、解释器、工作目录和冻结状态，后台记录 task id、操作名与耗时。

密钥变量及环境 token 注册到统一脱敏器，API key/authorization/password/secret/token 字段与 Bearer 格式屏蔽后再写文件和窗口。请求正文不额外打印到运行日志；原有 `runs/` 保存详细模型输入、响应和校验证据，运行日志给出定位路径。清屏、过滤和关窗不删文件。目录不可写或运行中磁盘故障记录内存错误与完整堆栈，主程序继续运行。
