## 1. 先找到实际生效的位置

`PromptSmithApp(GuidedFlowMixin)` 定义于 `src/promptsmith/ui.py`。初始化调用的 `_build_layout()` 来自 `guided_flow.py`。当前需求页、方案页、结果页和主动作也主要由 Mixin 定义；Skill 页在 `ui.py`。

`GuidedFlowMixin` 继承 `ConversationWorkspaceMixin`。`conversation.py` 中的 `conversation_cards()` 和 `conversation_plan_text()` 为只读呈现；统一输入调用现有 `submit_guided_answer()` / `start_analysis()`，确认调用现有预览确认方法。卡片操作比对显示时的业务快照，避免旧内容静默生效。Notebook 索引仍为 0 对话、1 方案详情、2 Skill 详情、3 结果详情、4 设置，不能仅按可见导航按钮推测索引。

`ui.py` 中 `_legacy_build_layout`、`_legacy_build_requirements_page`、`_legacy_primary_action` 等是历史实现，修改它们可能不会影响当前界面。主题与窗口配置仍由 `_configure_root()` 处理。

## 2. 首轮设计建议

五个用户阶段现由对话中的卡片承载：描述任务、澄清需求、确认方案、选配 Skill、交付提示。后续视觉调整应保持固定输入、逐题回答、明确确认及可选 Skill 路径。

建议浅色内容区配深色导航和蓝青色强调色。优先定义中文字体层级、间距、表单、按钮、卡片、提示状态及图标；用同一套规范制作 PPT 和技术图。

页面上始终能回答：我正在做什么、已完成什么、现在是 AI 在处理还是在等我、下一步在哪里。主要操作突出，低频设置折叠，长文案可完整展开。对内部 M1/M4、Schema、ID 等信息提供诊断详情入口。

## 3. 必须设计的状态

| 区域 | 至少覆盖 |
|---|---|
| 模型设置 | 未配置、待确认、已确认、修改后待重新确认、探测中、探测成功、探测失败、正式请求失败 |
| 需求 | 初始、分析中、待回答、可核对、用户修改后待分析、保留未知的草稿 |
| 方案 | 未生成、生成中、可编辑、已确认、依据变化而过期、生成失败保留旧方案 |
| Skill | 未搜索、本地处理中、本地有/无结果、网络处理中、部分成功、无结果、失败、已选择 |
| 交付 | 草稿、可复制/导出、有待补充事项、来源失效需重建 |

搜索结果卡片至少展示：名称、适合解决的工作、推荐原因、来源链接或本地路径、信息不足的说明、选中状态。读取状态是简洁说明，无需做成额外操作关卡。

推荐系数表达相对推荐强度，不是成功概率；保留完整正文、正文节选和仅元数据的证据说明。AI 失败时可以选择粗筛参考项，但不能把“尚未核验”改成“已确认适用”。搜索反馈显示真实索引复用、初筛及内容核验阶段，不用假的百分比或把“最多两次适配筛选”表述成整个联网/整合过程只调用两次。重新设计列表时保留默认 6 项、展开/收起、降序、选择/取消及已选项可见性。

后置待补充项应可在最终提示中阅读并带出；不要新增末端确认墙。技术错误要说明可执行的恢复操作，保留用户已经输入的内容。

## 4. 与业务逻辑连接的约定

- 页面输入通过现有 `_sync_input`、会话编辑/确认方法落地；不要直接给 `confirmed_*` 字段赋值。
- 主按钮文字与动作取同一状态判断，避免“提示处理冲突，点击却无反应”重现。
- 需求、方案和 Skill 改动保留来源与版本失效逻辑；取消选用调用真实取消/重建路径。
- 网络调用继续通过后台提交和主线程回调，状态文案只显示实际已发生的进展，不伪造百分比。
- 展示完整问题与选项，不按固定字符数裁掉语义，也不把问题的必要后半段放进另一个隐藏解释区。
- 暂存、返回、失败、取消和恢复后的内容可见；不要仅在理想成功路径上设计页面。
- 文案与色彩表达状态时保持一致；错误、警告、成功同时有文字，不能只靠颜色。

## 5. 与功能队员的边界

UI 队员可直接修改布局、样式、呈现文案、视觉资源和可访问性。业务结构、模型输出格式、来源校验或确认条件有变动时，在 PR 中说明目标与影响，与负责模块的功能队员共同检查。

如果选择 Web 或新的 UI 框架，需要先定义可序列化的状态接口、事件接口、异步任务和文件操作方式。当前仓库没有可直接连接的前端 API；本轮交接不要求更换技术栈。
