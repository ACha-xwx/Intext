# 踩坑与防回归

这些记录帮助队员和 AI 快速定位，不要求重新修复已解决的问题。当前未解决范围见末尾；历史原始报告见 [归档](archive/README.md)。

| 问题 | 根因/经验 | 修改时应保留的行为 | 相关入口或测试 |
|---|---|---|---|
| 改了 UI 却看不到变化 | 当前布局由 `GuidedFlowMixin` 提供，旧实现仍在 `ui.py` | 先确认实际方法解析和调用入口 | `guided_flow.py`；`test_guided_ui.py`, `test_guided_state.py` |
| 主按钮文字正确但点击无反应 | 标签与动作曾维护不同判断顺序 | 同一主动作决定文案、可用性和派发 | `run_primary_action`；UI 测试 |
| 回答后重复问，或忽略一个回答中的多条信息 | 历史问题关联、来源和增量合并不完整 | 已有回答保留；关闭缺口需有实际依据 | `m1.py`, `workflow.py`, `session.py`；M1 回归 |
| 追问句子被截断、选项不见 | 问题与解释拆分、长度处理使语义断裂 | 一起展示完整问题与选项，允许换行/滚动 | `test_question_display.py` |
| 模型返回 400，但连接测试成功 | 探测和正式结构化生成的参数不同，转发服务兼容性不同 | 以正式请求形状定位；协议字段不能混用 | `api.py`；`test_api.py` |
| JSON 截断后要求重填或丢回答 | 将不完整返回当作业务结果，或失败恢复入口不正确 | 失败输出不应用，原回答保留，显示明确重试入口 | M1 截断/UI 回归 |
| 旧请求覆盖新配置或新任务 | 只比较配置值，忽略 A→B→A 或请求世代 | 保留 request ID、版本快照、配置世代和迟到保护 | `workflow.py`, `delivery_workflow.py` |
| 空步骤也能确认方案 | 生成草稿可不完整，但确认环节未检查执行字段 | 草稿与确认校验分开；动作、输出、检查标准需可用 | `m2.py`, `session.py`；M2 回归 |
| 合理方案因新增未知被 M2 拒绝 | 旧规则要求来源缺口编号完全相等，新增项又被强制填写缺口编号 | 入站归并补回原未知，新项以 null 来源及真实关联需求表示；同源不同问题可共存 | `test_m2_unknown_recovery.py`；`merge_plan_unknowns` |
| 升级后旧最终提示被撤销确认 | 新渲染文案或基线字段改变已保存结果的比较值 | 新草稿用显式标记启用新说明；旧结果按旧基线/正文严格核对 | `finalization.py`；旧确认保存重开测试 |
| 生成期间换页后看不到补充指引 | 页面保护分支替换了生成成功状态文案 | 保留当前位置，同时保留“未知可在使用时补充”说明 | `test_m2_guidance_ui.py` |
| 删除矛盾项后仍一直阻断 | 旧冲突参与方或复核记录残留 | 重新核对实际参与方，一般未知允许带入草稿 | `test_guided_state.py`, `test_conflict_participant_integrity.py` |
| 最后一步复制/导出被后置复核锁住 | 旧设计把所有复核项当作必须先处理 | 一般补充项写入最终提示，用户继续使用；保留引用/版本有效性校验 | `test_final_closure.py`；最新 guided flow |
| 搜索结果为零但不知道是否在运行 | 查询、合并、AI 分析和 UI 状态脱节 | 明确本地/网络进行中、空结果、部分成功、失败与完成 | Skill UI/网络发现测试 |
| 普通网页或普通仓库被当成 Skill | 只凭关键词相关性，没有 Agent Skill 身份判断 | 接受真实 `SKILL.md` 或明确索引身份；相关普通网站不能直接选用 | `test_skill_network_discovery.py` 等 |
| 某一网络来源失败导致整个搜索失败 | 单一路径依赖、串行等待或过严读取要求 | 三路并行、独立失败处理、保留有依据候选 | `skill_network_discovery.py`；每路 45 秒预算测试 |
| 本地目录换电脑失效 | 用开发者固定绝对路径作为前提 | 动态用户目录、忽略不存在路径、允许零结果继续 | `local_skill_search.py` |
| Skill 搜到了但 M4 契约拒绝 | 搜索来源状态与 M3/M4 枚举不同；也可能在运行旧 EXE | 接受实际证据状态，同时区分摘要与正文，不任意删除语义检查 | `test_skill_handoff.py`, `test_m3_m4.py` |
| 最终提示没有告诉其他 AI 如何用 Skill | 只有笼统方法描述，名称/来源/用途未稳定传递 | 从绑定补齐名称、链接/本地路径、关键工作、执行步骤 | `test_skill_handoff.py`, `finalization.py` |
| 取消 Skill 后还残留其链接 | 共享贡献未重新计算来源 | 按当前绑定重建，保留其他仍有效贡献 | `test_skill_handoff.py` |
| 正文已读取却仍显示“未读取” | 固定文案与实际证据脱节 | 依据 `source_read` 等实际状态渲染 | `finalization.py` |
| 启动旧包误判修复无效 | 本机多个 EXE/窗口并存，名称相似 | 对照构建时间、提交版本和哈希；验证同一文件 | `verification/baseline/skill_handoff_20261008/` |
| EXE 缺资源，源码正常 | Loader、spec、测试路径或兼容文件不同步 | 显式检查打包资源，做独立目录启动 | `paths.py`, `PromptSmith.spec` |
| 滚轮、嵌套表格与菜单异常 | bindtag 顺序、焦点归属或关闭清理不正确 | 内层可滚时优先；主页面仍可到达底部；关闭后不残留回调 | `test_mousewheel.py`、UI 布局检查 |
| 将测试通过误报为模型效果好 | 混淆 fixture、HTTP stub、真实 API 与用户试用 | 报告证据类型、版本、范围和实际结果 | `verification/README.md` |

## 当前历史失败

前次全量记录中 12 项失败属于旧测试/契约不一致，完整节点清单见 [2026-10-07 基线报告](../verification/baseline/agent_skill_target_20261007/results.md)。主要涉及旧 M1 版本断言、旧末端阻断与按钮导航语义、兼容字段与恢复请求次数。

本次整理的实跑结果另见 [交接验证](../verification/repository_handoff_20261008/results.md)。不要删除这些测试或统一标记跳过来制造通过；如果以后明确处理，应先确认当前产品语义，再分别更新契约说明与有意义的测试。

## 后续真实验收缺口

- 最新真实模型的完整 Skill 流程与下游任务结果。
- 跨机器、本地无 Skill、接口失败及真实 Windows DPI 的体验。
- 对照实验、实际用户反馈与整体时间/成本。

这些是待验证事项，不能仅因旧回归通过就写成完成。UI 改动优先复验受影响路径，历史通过项没有新证据时不重复跑。
