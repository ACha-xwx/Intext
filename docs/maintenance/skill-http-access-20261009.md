## 源码修改

- `skill_http.py` 提供一轮搜索共享的 HTTP 会话。GitHub API、原始 Markdown、JSON 索引与网页采用对应 Accept，网页提供常用兼容 UA。兼容请求头不能保证解除网站侧的访问限制。
- 已有 GitHub token 仅发送给官方 HTTPS `api.github.com` 的标准端口，不发给索引、GitHub 网页、正文域名或第三方。默认传输的重定向处理器剥离跨来源凭据；同一官方 API 重定向可继续鉴权。非法头字符的凭据被忽略并提示匿名继续，避免底层异常回显秘密。没有新增凭据保存或模型调用。
- 本轮元数据/正文缓存上限 12MB、64 项，三条来源共享，不持久化；相同已完成 URL 不重复下载。全局来源结果缓存键区分 GitHub 凭据，避免换凭据仍命中匿名结果。并发首轮同 URL 在缓存填充前仍可能分别请求，未声称单请求合并。
- 403 区分限流、访问拒绝和验证页面，429 为限流，521 等 5xx 为上游服务不可用，401 为鉴权问题。日志记录脱敏域名/路径、状态、类别、剩余额度、重置时间、数字 Retry-After 与完整异常链；不打印凭据、请求头或错误响应正文，不输出 URL 查询值。
- 本轮暂停受限入口，转用其他来源，不进行无界重试或阻塞等待。GitHub 的 search/core 限额可按资源暂停；普通文件的 403 只影响其路径，不把整个网站的其他公开文件隐藏。暂停只持续本轮，用户之后可重新联网搜索。
- 索引和搜索引擎遇 401/403/429/5xx 或验证页面不再反复换词访问；GitHub API 受限后仍保留已有公开页/原始内容降级与真实 Skill 元数据。没有把普通网页或一般仓库直接当成 Skill。
- 主界面显示部分来源可用、已跳过受限入口以及下一步；全部失败时已有候选和绑定保留，可选择现有结果、跳过 Skill 或稍后重试。三来源线程继承各自的调用上下文，保留会话取消边界。
