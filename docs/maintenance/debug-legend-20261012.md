# Debug 图例筛选与历史阅读

2026-10-12；本轮范围为独立 Debug 窗口的 WebView2 默认界面及 Tk 回退，未更改业务状态、模型调用或日志采集归档。

## 当前交互

- 右上角显示 DEBUG、INFO、WARN、ERROR、CRITICAL 的颜色圆点、类型和条数；隐藏项文字和圆点灰显，仍可点击恢复。
- 点击某一项只改变该类型的显示。原日志级别下拉作为批量筛选预设，独立切换后显示“自定义”；隐藏后的新日志继续累计，重新显示时可查看。
- 条数按当前显示缓存中、最近一次清空标记后的完整日志记录统计。多行异常是一条记录，计数不受筛选或显示行数裁剪影响；缓存淘汰后计数相应减少。
- 自动滚动开启时，仅刷新前已经位于底部才跟随新增日志。上翻后保持阅读行和位置，回到底部后自动恢复跟随；关闭自动滚动后，即使原在底部也不跟随。主动重新开启自动滚动会移到底部。
- 清空只清显示和对应计数。复制当前可见日志；“保存日志”继续保存完整内存归档，包括隐藏、清空前和超出显示缓存的记录，完整异常及脱敏继续保留。

## 根因与实现

旧实现只判断自动滚动开关，每次收到日志都移到底部。Web 重建 DOM、Tk 删除旧行也会改变阅读位置。初始布局中，缓存总数和保存状态在恢复位置后才更新，还会使日志区域高度变化。

Web 在布局更新前捕获日志 ID、原始记录行号和像素偏移，完成头部/页脚及正文更新后恢复；记录内裁剪保留原始行号。浏览器原生滚动锚定关闭，避免双重调整。无条目、偏好或布局状态变化时不重绘、扫描锚点或写入滚动位置；减少缓存上限立即裁剪，不等待新日志。

Tk 使用记录 tag、可见行、剩余行数和像素偏移，既保留增量追加，又处理缓存和行数淘汰。图例按窗口宽度换行，用户切换级别才记录操作诊断。没有增加刷新、滚动或计数的逐帧日志。

## 验证边界

生产 Chromium DOM、实际 Tk 控件及 RuntimeLog/DebugApi 的 52 个不同节点通过；实际 WebView2 隔离窗口的 14 项检查通过。覆盖五级颜色/计数、隐藏/恢复/键盘筛选、浅深主题、600px 小窗口、长堆栈、缓存缩容、历史位置和底部跟随、清空、完整手动保存、错误恢复与脱敏。
