# 对话回复组件与流式思考

更新：2026-10-10。按用户提供的 AI 回复 TSX 和浅深截图复刻回复区；示例中的安全审计、文件/终端操作仅是样式资料，没有作为本产品的运行功能。

## 用户可见变化

- 删除原欢迎说明和空状态进度卡片；未发送目标时，对话区中央仅显示“让我们一起把一个目标变成一份完整的提示词吧。”。
- 整个主工作区使用连续浅色/深色背景：外壳、导航、任务标题、对话、输入框周围和底部状态一致，隐藏 Notebook 分区外框。空任务隐藏任务标题行；重复“下一步”卡片移除，确认操作在对应回复旁，必要的重试/补全模型入口仍以简洁底部操作显示。设置内部继续默认组件。
- 用户消息为右对齐浅灰/深灰圆角气泡；AI 回复为无外框正文。过程区保留点阵状态、总折叠、细左线、可独立折叠/滚动的思考内容及上下文条。
- 上下文条来自本次请求捕获的真实目标、已确认要求数量、已有回答、当前方案步骤和所选 Skill 数量；没有虚构文件读取、终端执行或搜索结果。
- 思考内容只来自服务端公开返回的字段；没有思考字段时说明本次服务没有返回可展示内容。正文支持 Markdown H1–H6、Setext、HTML 标题、粗体、行内/围栏代码和引用。程序固定提示词分节用展示标签排出层级，复制/导出的业务正文不改变。
- 每个待答问题下有独立多行输入和“提交回答”；空白/忙态禁用，Ctrl+Enter 提交，选项填入该题回答框。各题可以按任意顺序回答，刷新/主题切换保留其它未提交草稿；最后一题提交后统一整理一次。
- 原“我不确定 / 使用时再补充”、访谈轮次和第五轮后逐轮授权仍有效。问题的内部原因不作为用户提问显示；回答不自动确认需求或方案。
- 需求表格、方案编辑、Skill 比较表、最终提示词复制/导出和会话保存继续使用已有业务入口，仅适配回复外观。设置页继续使用默认组件，所有字体由平台默认字体派生，不生成字体文件。

## 接收与呈现

`streaming.py` 的 worker-local `observe_stream()` 由 `ui._submit()` 绑定。被观察的生成调用在 `_post_json()` 添加 `stream: true`，现有 DeepSeek `thinking.enabled` 与思考强度参数继续生效；测试连接和模型列表不进入回复时间线。

HTTP 响应为 SSE 时按完整 UTF-8 行/事件接收并分离思考和正文：Chat 读取 `delta.reasoning_content`，Anthropic 读取 thinking block，Responses 读取服务公开的 reasoning/summary delta。用量、结束原因、拒绝和截断仍交给原协议解析器；收到协议终止事件立即停止读流。仅返回 JSON 的代理走整包兼容，思考只能在其完整响应之后展示，不将这种情况称为真正实时。

业务正文先收齐后恢复为原 envelope，再由现有 M1–M5/筛选解析器应用。未验证的半个 JSON 不会当成需求。断流、服务错误、超时和解码失败保留部分 envelope、正文、公开思考及完整异常链，主界面保留下一步/重试说明；达到 token 上限继续按原 `truncated` 合同处理。

`response_workspace.py` 用队列在 Tk 主线程消费事件，每批合并思考增量；一次处理最多约 6ms/2000 事件。只有开始/结束/异常等状态变化重建其它卡片，活跃 `ResponseTrace` 控件和动画实例跨刷新保留。后台线程不访问 Tk。

流式事件与业务完成之间增加同队列屏障：完整元数据先被主线程应用，再执行成功/失败回调，防止已完成请求保存为 `working`，重开误显示取消。队列仍分帧有界消费，完成回调不等待文字动画排空，不阻塞长思考。真正未完成的记录重开时仍正确标为取消。

`AdaptiveWriter` 每 16ms 安排一次增量插入，根据积压量增加单帧字符数，并设置约 4096 字符上限（完整字素可略超过）。它不全量删除/重画思考，不在收到结束信号时直接 flush 到末尾；结束后仍逐帧排空。CRLF、重复空行和换行后的空白归一为单个换行。Python Unicode 字符、组合符号、emoji 修饰/连接和旗帜不按 UTF-16 单元截断。用户滚动离开底部时，新增文字不强制拉回。

16ms 是调度间隔，不等于显示器 FPS。实测结果和机器限制见 [验收](../../verification/response_workspace_20261010/results.md)。

## 会话和取消边界

公开思考与过程元数据保存在 `SessionState.control.response_traces`，带已答条数位置、模型/协议和状态；保存/重开时可回看及复制。重开时旧 `working` 记录改为 `cancelled`，不恢复旧网络连接。未提交问题草稿属于界面状态，不作为已确认要求。

模型输入使用原有字段投影，展示 trace 不进入 M1 控制白名单或其它模型输入，防止长思考增加后续 token。进程中仍以 SessionState 为业务事实源。

事件同时核对 TaskScope、会话实例 token 与 M3/M4 请求取消标识。新建/打开关闭旧动画并丢弃迟到事件；显式取消整合只关闭该请求的 trace，包括网络已经结束但动画尚未排空的情况。urllib 阻塞中的网络读取仍可能等待返回，但不会污染新会话或继续展示旧输出。

## Debug 与验证

整页融合新增主题生命周期与完成屏障等待 Debug；错误继续记录完整异常链。

细滚动条自然请求高度为 1px，由所属内容决定实际高度；不得恢复 Canvas 默认高度，否则短正文会因显示/隐藏改变自身高度而反复布局。需求长原文测试用有限 idle 步数防止这类循环把验收本身卡住，仍核对完整文字、只读状态、编辑失效和重开。

新增接收开始/结束、SSE 事件数、思考/正文字符数、耗时、兼容 JSON、trace 生命周期、逐题提交、界面重置和动画排空统计。完整网络/后台异常链沿原日志机制记录。运行日志仍仅内存收集，用户点击 Debug“保存日志”后才落盘；模型证据 `runs/` 使用原存储合同。

新增 `tests/test_streaming.py`、`tests/test_response_workspace.py`，更新旧底部输入回答测试为内联合同。隔离 LOCALAPPDATA、合成凭据、localhost SSE 和 Windows Tk 验收；无真实模型、EXE 构建或 Git 远程操作。详见 [验证记录](../../verification/response_workspace_20261010/results.md)。
