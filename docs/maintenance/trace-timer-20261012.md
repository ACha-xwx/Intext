# 思考区读秒卡顿修复（2026-10-12）

用户反馈思考区“正在处理… · 5.8秒”读秒卡顿。本轮只修改Web工作区的耗时呈现，保留思考文本动画、业务状态与请求参数。

## 复现与根因

公共 `promptsmithView.applySnapshot` 入口传入working记录后，浏览器时间继续推进，而无新快照时读秒一直停在5.8秒。使用受控浏览器时间的失败回归稳定复现，见[原版失败](../../verification/trace_timer_20261012/red-controlled-clock.xml)。

排查三项假设：读秒依赖后台快照；长思考渲染挤占更新；数字宽度变化造成抖动。实际 `TraceView.update()` 直接用快照elapsed重写标签，正文rAF仅在有待输出文字时运行。因此后台同步有间隔或延迟时，读秒停顿。单独让时钟在无正文、无快照时运行即消除该停顿；长Unicode与宽度测试另外通过。

## 修改

仅生产文件 `resources/ui/workspace/workspace.js` 改动，新增 `tests/test_trace_timer.py`。

- working状态通过 `performance.now()` 单调时间与后端elapsed锚点计算当前显示值，复用既有rAF循环。仍显示一位小数，数字变化才写入对应文本节点。
- 后续working快照不会让当前读秒倒退或重复停住；终态明确采用后端最终elapsed，并停止读秒。
- 终态停止时，剩余思考内容仍沿用原Unicode渐进输出；折叠不暂停读秒，移除或切换会话走既有close取消rAF。
- 状态文字、数字和秒单位拆成文本节点，不改变字号、布局、字体或动画样式。等位数字与chevron位置测试通过，无需增改CSS。
- Debug新增计时开始/终态停止事件，包含记录ID、状态、耗时及monotonic-local方式；不逐帧写日志，保存仍由用户操作。

## 验收

8项新增回归、54项前端相邻及11项侧栏相邻，共73项通过。独立真实WebView2呈现使用合成快照与临时浏览器数据目录，13项通过，覆盖无新分片、迟到快照、长Unicode、三种终态、切换会话和诊断数量。规范/需求双轴复查各0发现。

原生第一轮包含刚映射窗口的初始布局停顿，后将启动预热与请求读秒分开测量；另一轮日志数量预期把done之后failed/cancelled状态误算为多次working退出，修正验证脚本预期，不改生产代码。早期焦点/文本/折叠测试的观察差异也已纠正，原始记录保留。

本轮真实WebView2证据是渲染检查，模型/业务输入为合成数据；未发真实模型请求、构建EXE或验证180Hz屏幕呈现。浏览器主线程真正被阻塞时，任何UI动画仍可能暂停，本修复消除计时与后台同步的耦合。完整结果见[验收](../../verification/trace_timer_20261012/results.md)。
