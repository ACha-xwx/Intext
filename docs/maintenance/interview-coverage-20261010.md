# 前期全面访谈与需求比较表

用户希望前期把会影响方案的细节问得全面，减少方案或最终提示反复生成。访谈一般四至五轮；用户最新补充允许第五轮结束及以后每轮先问是否继续，明确继续仅增加一轮。截图中的已确认需求纵向长卡片也改为比较表。

## 原因与改动

旧 M1 首轮/增量默认少量问题，输出 Schema 强制最多三题，增量偏向局部更新；M2 只带被正式需求引用的来源，部分真实前期回答可能没有传入规划。

现在首轮和增量检查目标、受众/场景、交付、范围、材料取得、环境、风格、限制和验收中与任务相关的维度。UI 重构特别核对现有问题、页面、可改范围、源码/截图/入口提供方式、视觉参考和回归标准。已给信息与明确暂缓内容不重复问，不强制用户把源码上传到本程序。取消三题硬上限，一题一个决定，依赖前提的分支留到后续一批。

`interview_rounds_used` 计已展示的问题批次，`interview_round_limit` 为已授权上限，默认五轮。卡片数量、最后整理与内部修正不单独计轮。第五批的完整队列固定保存，避免计数到五时漏掉本地派生问题。每个额外轮次需点击“继续，再问一轮”，只授权下一批；轮次、授权和剩余卡片随会话保存，新任务归零。信息充分可以提前复核。

授权用完只整理已答内容，保留事实与未知，不能自动生成下一批。收尾卡片展示剩余未知，可输入补充或点击“结束追问，使用时再补充”。暂缓只记录用户决策，需求和方案仍须正常确认；确认校验始终检查完整未知集合，不因隐藏自动题卡而跳过核对。请求失败时继续保留已答/授权，不自动消耗一轮。

M2 使用紧凑问答记录，每条仅包含问题、回答状态和真实答案 source ID，正文在 relevant_materials 传一次。已答或已明确暂缓的事项应在规划中承接，真正新发现的未知一次列全。上下文不是自动采用的额外硬约束，未知仍随最终提示保留。

## 需求表格

统一时间线的已确认/待核对需求共用表格：需求类型、内容、内容来源、确认状态。长文单元格显示摘要，选中一行在表格下阅读完整原文；修改、移除和解释/修改建议的采用操作复用原业务方法。刷新保留仍存在的选中行，横纵滚动可查看长内容。修改已确认项使原需求确认、方案和已有提示失效，旧卡片操作仍拒绝。

## Debug 与资源

M1 日志记录请求模式、策略、已用/授权轮次与剩余批次；额外继续/结束记录用户选择，落地记录新批次。M2 日志记录紧凑问答和来源数量。异常保留详细堆栈，不记录密钥或重复答案全文，Debug 仍仅点击保存才写日志。
