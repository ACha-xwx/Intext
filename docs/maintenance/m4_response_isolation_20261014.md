## 复现和根因

公共整合测试用缺少闭合符的合成响应复现：`canonical_body` 在导出前已经包含 `"schema_version"`、`"contributions"` 等整个响应。第一条测试红在正文断言，排除“只有导出器格式有误”的解释。截图未提供原始文本，不能认定远端具体是哪一处 JSON 语法错误。

`parse_m4_response` 把解析失败的原文作为 `unstructured_guidance` 写入第一个贡献的 `fallback_actions`。原有共享 `extra_notes` 还会把额外对象序列化成 JSON、模型错误字典直接字符串化。最终正文忠实渲染这些业务说明，因此复制、导出也被污染。

M4 现在仅移除单一完整 JSON 对象外的说明/代码块，内部仍通过严格解析与 request/task 身份检查。损坏结构化响应只产生简短引用指导说明；额外字段只保留自然语言字符串，不转储对象。模型错误仅提取可读 code/message/recovery_action。合法模型方法、来源、未知前提和普通自然语言恢复继续保留。共享 model_output 和 M3 未改。

原始响应继续保存在 RunEvidenceWriter 的 `response.raw.txt`；兼容事件与有效结果仍保存，Debug 增加 `unwrap_json`、`structured_response_omitted`（含解析原因）、`structured_note_omitted` 摘要，不包含响应原文。不增加网络重试或模型调用。
