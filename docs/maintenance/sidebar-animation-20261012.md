# 侧栏收起动画修复（2026-10-12）

用户反馈侧栏收起时历史列表立即消失，顶部快捷操作从页面下方升起。本轮目标是保持原展开/收起布局和业务操作，使动画连续、顶部控件稳定，并支持中途反向。

## 根因与复现

原样式叠加了两套收起布局：侧栏从 `100dvh` 过渡到 `66px`，同时立即切换横向排列与垂直居中。810px 高窗口的第一帧按钮约在 y=395，随后随高度缩小向上移动；历史列表则因 `display:none` 立即消失。

四组浅深主题、1440/720px 窗宽的逐帧测试先复现失败。单变量实验中，仅取消居中可把顶部控件底边恢复到57px，却不能解决列表消失；仅保留列表则仍有425px的顶部控件底边。两项根因独立成立，见验收目录保留的原始失败记录。

## 实现范围

仅修改 `resources/ui/workspace/index.html`、`workspace.css`、`history.js`，新增 `tests/test_sidebar_animation.py`。

- 侧栏保持完整高度；背景向左退出，历史内容用300ms淡出和24px左移，动画结束后隐藏。
- 展开头部与收起胶囊分别保持固定顶部坐标，先120ms淡出、再120ms淡入。共享品牌标记始终可见。首版水平换序会让按钮交叉，双轴审查发现后补充失败测试并改为固定两组布局。
- 隐藏组与收起历史立即设为 `inert`，同步 `aria-hidden` 与两个展开按钮的 `aria-expanded`；原焦点在退出区域时转到进入组的展开/收起按钮。
- 搜索、新建复用原有业务回调。关闭搜索后焦点返回对应入口；收起区域不遮挡工作区输入。
- 减少动画偏好下取消过渡和延迟；浏览器原有收起状态持久化继续保留。
- 每次切换只记录一条 Debug 事件，附展开状态、动画方式与减少动画偏好；不新增逐帧日志，日志仍手动保存。

## 验收与边界

最终11项新增动画回归与54项相邻浏览器回归全部通过。独立真实 WebView2 窗口使用临时数据目录、合成历史及真实 Python 桥接，25项检查通过，包含历史读取、收起搜索、新建、快速反向和逐帧无交叉。浅深阶段截图已目视核对。

规范、需求两轴复查均无待修发现。早期测试使用不存在的焦点接口、减少动画初态按钮选择错误，以及原生验证脚本对卡片类别/程序点击焦点的错误假设已修正；原失败记录保留，不以修改业务迎合验证脚本。

源码已更新，未构建新版EXE、发真实模型请求或验证180Hz屏幕实际呈现。完整证据见[验收](../../verification/sidebar_animation_20261012/results.md)和[双轴审查](../../verification/sidebar_animation_20261012/review.md)。
