# 模型确认保存与启动恢复

日期：2026-10-10；当前源码行为，EXE 未重建。

此前 settings.json 已保存模型参数及加密密钥，但 `_confirmed_connection_state` 每次启动置空，导致已确认过的配置也需要重复点确认。现在明确确认时，配置、DPAPI 密文和 `model_confirmation` 同次原子写入，启动匹配有效后恢复确认状态。

确认记录包含版本及公开连接、规范化模型参数、加密凭据记录的指纹，不保存明文密钥或其散列。启动先解密，再核对实际配置与本地 ApiConfig；字段损坏、环境覆盖、凭据失败均保留设置页和下一步提示，不能误用旧确认。指纹用于绑定确认依据，不是设置文件的安全签名。

普通保存仅延续当前已有确认；模型/接口/密钥/模型参数编辑后需重新确认，测试连接成功也不确认。字体、搜索、Debug 开关和新建/打开对话不会丢失确认。尚未保存的模型草稿退出后丢弃，重启仍使用原来确认并保存的配置；明确保存草稿则移除旧确认。旧文件没有确认依据，只需在新版首次确认一次，此后记住。

Debug 包含确认保存、启动恢复、模型编辑失效、配置不符和失败堆栈；密钥脱敏，仍仅由“保存日志”写入文件。原子写入或加密失败不破坏旧文件，并保留重试入口。

验证范围和结果见 [验收记录](../../verification/model_confirmation_20261010/results.md)。没有读取用户生产 settings.json 或调用真实模型，保留此前所有未提交工作。
