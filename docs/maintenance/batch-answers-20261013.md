# 本轮问题回答一键提交

## 用户目标与范围

任意当前问题回答框按 Enter，或点击它旁边的圆形发送按钮，一次提交当前轮所有已填写的回答。空白题保留，不自动跳过；Shift+Enter 换行，输入法候选确认不发送。历史已提交回答及底部消息输入不加入这次提交。

这是用户暂缓回归后四项待修中的第1项。实现时只编写测试，按要求等待其余问题修完；第四项完成后已统一执行公开边界、生产DOM与隔离WebView2验收。不请求真实模型、不提交推送。

## 根因与实现

此前工作区事件只传单题 ID/text，Controller 也只调用单题入口。不能循环执行原 UI 提交：它逐次刷新，可能丢失尚未提交输入并多次触发分析。

SessionState 在工作副本上完成每条已有 record_question 逻辑、解释拒绝和草稿清理后一次提交；保持原对象身份供两个 workflow 使用。没有新增确认、模型请求参数或自动跳过逻辑。共享业务入口仅刷新一次，再按剩余题数判断是否整理。自动整理启动异常不把已保存回答误报成未提交，使用右上错误通知和 Debug 提供下一步。

Web 只从当前快照对应的可见问题视图采集非空输入，单次通过已有 command/草稿同步/会话 stamp/忙态保护提交；提交中冻结问题输入，成功且同会话才清对应草稿。服务端返回具体 submitted IDs，兼容旧 id/text 调用。Tk 回退采集当前题输入并复用相同业务入口，任意问题发送按钮按整批是否有回答启用。未答题与它们的空白草稿继续保留。

## 统一运行的验收场景

- 输入第一/第三题后，在空白第二题按 Enter 或发送：只记录第一/第三题，第二题保留，不调用模型。
- 整批都有内容：一次 bridge answer，一次刷新，最多一次整理，模型输入包含每条回答；分别保留来源和共同提交组。
- Shift+Enter 仅换行、IME 不误发；空批/忙态不提交；重复 Enter 不创建重复动作。
- 过期/重复问题或第二条记录失败：整批业务回滚，输入及持久草稿保留，完整异常脱敏记录。
- 旧会话 stamp 拒绝写入；成功后清理仅提交题的草稿，保存重开恢复未答题及对应进度。
- Tk 回退同样批量提交、空题按钮可提交其他已填回答；已有单题 bridge 合同仍兼容。
- Debug 显示简明的批次数量与剩余问题，原始记录保留 IDs/字符数及完整异常，不记录回答正文、不自动写盘。
