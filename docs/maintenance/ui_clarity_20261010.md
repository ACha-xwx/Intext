# 字体清晰度、菜单选择与交互修复

2026-10-10 后续变更：用户已取消自定义字体，本文件中的混排、字体预览、缓存及准备线程说明仅保留历史证据，生产实现已移除；当前行为见 [系统默认字体](native_fonts_20261010.md)。图标/DPI/菜单相关修复继续有效。

用户反馈文字/图标不清晰、数学字体撑高界面、选中对勾偏上、思考强度未选中，要求删除模型菜单的两个额外按钮并默认 High。

## 根因与修复

- 源码没有 DPI 感知声明，系统缩放可能整体拉伸窗口。现于 Tk 创建前设置 Windows System DPI 感知，尊重宿主已选模式；EXE spec 同步 manifest。启动窗口按密度适配，同时保持 16:9 和屏幕边界。
- 72px 图标原先每隔三像素抽样成 24px，现由 Pillow LANCZOS 平滑缩放至当前密度对应尺寸。选中勾改为独立平滑图像，居中于名称行，不依赖字体基线；菜单字号增加一级，搜索图标也独立绘制。
- v4 中文优先丢失了西文 hint，嵌入宋体位图又会让 Windows 对整个混排字体关闭 ClearType，导致英文笔画发虚。v6 保留西文完整字形程序、fpgm/prep/cvt/gasp；使用中文轮廓及不依赖另一字库全局表的局部 hint，移除混排位图表。原生宋体统一模式仍由 Windows 正常加载。已用真实 Canvas 截图确认 11pt 英文样本与原生 Times New Roman 像素一致。
- 数学字库的度量包括大型公式。原复现同样 12pt，行高 17→69px，普通按钮 27→79px，输入区 134→238px。混排 hhea/OS2 改用正常 UI 行高；统一模式仅为度量异常字体生成私有副本，普通系统字体保持原族。不会改变源字形或系统字体文件。
- 默认 auto 不属于四档，导致没有高亮项。新默认和切换模型默认均为 High；同模型重复选择保留当前档。旧 auto/omit 在原确认依据核对后迁移为 High，有效接口确认保留；`composer_defaults` 标记区分新文件，设置页明确保存的新 auto/omit 或其它档仍按用户选择恢复。
- 菜单每次销毁重建、逐字截断和字体反复创建造成卡顿。现隐藏复用菜单、复用命名字体、二分截断、缓存绘制/布局状态；字体/主题变化和控件销毁释放缓存，目录分类变化重建。没有固定 30 FPS 上限，50ms 后台完成队列轮询不限制输入与滚动。

## 选择与设置边界

菜单删除“模型设置”和“确认选择”，仅保留分类、搜索、模型与思考强度。已确认的相同接口内，用户点击选择即应用并加密保存；接口未确认/变更、密钥变化或其它参数草稿，仍从右上角设置核对。不能通过选模型顺带确认其它草稿，测试连接仍只测试。保存失败保留原文件、给出重试说明和完整异常。

SessionState、后台版本和取消保护保持原工作流。新增 DPI/密度、图标准备耗时、菜单复用耗时、选择应用/待确认原因、旧默认迁移日志。Debug 保留蓝/白/黄/红与脱敏，运行日志只在用户手动保存时写盘；字体缓存和模型证据遵循各自合同。

## 运行与验证边界

Pillow 为新增运行依赖。字体缓存版本自动区分，重启生成新缓存，用户无需清除系统字体。首次窗口先显示，未缓存字体在首次绘制后后台准备；缓存启动直接加载。准备结果通过版本号和关闭状态保护，在 Tk 主线程更新共用字体及菜单，保留输入草稿。字号变更不重复生成相同字体。准备失败保留可用字体并给出下一步提示，完整原因进入 Debug。去除无必要的全字库 subset 减少准备成本，仍需后台生成时间；换字体自然会改变字形宽度。System DPI 使用启动时系统密度，未宣称运行中跨显示器的独立 DPI 适配。
