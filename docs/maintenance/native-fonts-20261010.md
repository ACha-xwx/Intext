# 取消字体自定义，直接使用平台默认

2026-10-10：用户撤回中文宋体、西文 Times New Roman 和自定义字体的要求，要求全部元素直接使用默认字体，默认族名不写死。

## 原因与改动

此前 Tk 的按钮、表格和 Canvas 单控件通常只接收一个字体族。为满足当时指定两种字体的要求，实现过合并本机字形、私有注册和磁盘缓存；字体准备及度量处理增加了复杂度。普通系统字体本来可以直接使用，本轮撤除整套合成路径。

- 设置→界面删除中文字体、英文与数字字体、分别设置开关和预览；保留独立字号、窗口尺寸和浅深主题，共计 32 项偏好。
- `Typography` 从 `TkDefaultFont` 读取平台族名/属性，为控件字号和粗体层级派生内存 Font；不硬编码族名、不改写 Tk 原有命名字体。汉字缺字回退由 Tk/Windows 处理，系统标题和文件框仍由 Windows 绘制。
- 删除字体文件扫描、合成、度量副本、私有注册、磁盘缓存、后台线程、启动延迟和完成回调。已有 `ui_font()` 调用点保留，新增控件也使用这个入口。
- 移除 requirements/pyproject 的 FontTools 依赖和 PyInstaller 动态模块收集；Pillow、图标资源与 DPI manifest 继续使用。
- 旧 `chinese_font` / `latin_font` / `split_fonts` 偏好加载忽略；普通保存和 Debug 独立保存会清理这些字段，不删除用户已有缓存目录。

字号保存只更新内存 Font、样式及菜单布局，保留输入草稿。主题/字号变化仍释放已缓存的模型菜单。SessionState、模型请求/取消、模型确认与 DPAPI 合同不变；退休界面字段不参与模型确认指纹。

## Debug 与验收

Debug 记录平台字体来源、实际族名和字号、生命周期，以及旧字段被忽略的字段名；不记录旧字段值。取消原合成/缓存/后台完成诊断。设置失败仍保留完整异常，级别颜色、完整内存记录、手动保存合同继续生效。

174 个定向节点与两次实际 Windows Tk 进程共 72 项检查通过。检查浅深主题、设置页、模型菜单和 Debug 默认字体；旧设置与加密密钥/确认恢复成功，未加载 FontTools、启动字体线程或通过 Python 访问字库/缓存，无新的字体文件。两个实际首次显示耗时 3.336 / 3.535 秒；独立源码入口 smoke 退出 0。详情见 [本轮验收](../../verification/native_fonts_20261010/results.md)。本轮没有真实模型调用或新版 EXE 验收。

此前 [自定义字体](typography-20261010.md) 和 [清晰度](ui-clarity-20261010.md) 的字库准备结论仅保留历史证据；其中图标/DPI/菜单修复继续有效。
