# 访谈耗时、等待日志与重复追问修复 · 2026-10-11

本轮对应用户三项反馈：整理回答耗时约 250 秒、等待回答时 Debug 刷屏、已经回答的范围问题再次出现。用户明确选择“所有阶段都保持当前思考强度，只精简提示和上下文”。本轮源码修改及离线回归完成；没有发起新的真实模型请求，也没有构建 EXE。

## 根因与范围

读取该次请求已有的运行元数据后确认：耗时 256431 ms，输入 10766 tokens，输出 55622 tokens，其中 reasoning 54075、正式回答约 1547，finish=stop，没有自动修正重试。主要等待来自模型的一次大量推理，不能归因于界面打字效果，也不能通过一次离线检查承诺新的响应时间。

M1 原先叠加历史基础提示和当前补丁，首轮有 35769 字节 system 指令，增量有 21658 字节。旧的轮次、跳过、建议选项等规则与当前行为存在重复或冲突。`SessionState.validate_unknown_reviews()` 同时用于真实操作和界面状态投影，在有待回答问题时每次调用都写 DEBUG，导致等待态轮询不断产生同一事件。重复提问原来主要依赖模型与 gap ID；换 ID 或重排措辞后，已答题仍可能作为新问题进入本地核对投影。

应用修改限于 `session.py`、`clarification.py`、`m1.py`、`workflow.py`、三份 M1 提示及资源声明；相关回归与资源文档同步。API 客户端、UI 和偏好文件与本轮修改前快照字节一致。会话事实仍由 SessionState 管理，确认、取消、版本和迟到响应保护沿用现有路径。

## 实现

- **等待态日志**：移除只读校验中的重复 DEBUG。回答、确认、访谈状态变化、实际失败和完整异常证据继续记录，不通过全局降日志级别隐藏错误。
- **重复问题**：M1 解析与本地需求核对共用有限的问句归一化。规范空白、标点、大小写及少量疑问词/编辑动词；支持二选一分句交换顺序，但保留对象、条件、数量和否定关系。命中且模型本轮仍判定该答案 partial/unresolved 时，改为引用上一条回答、要求明确其中的决定，不重新呈现原二选一问题。
- **答案对应**：优先引用最近同一 gap 的答案；跨 ID 只回退到实际匹配历史，不引用同范围的其他问题。完整答案留在历史和输入证据，题卡只显示最多 240 字的引用摘录。含“是否”的答案不会自动变成肯定。用户主动补答仍能打开原题，新增范围和新细节仍可询问。
- **提示精简**：首轮改为 `M1_contract_v0.1.txt` + `M1_system_v0.25.txt`，增量改为同一 contract + `M1_incremental_v0.18.txt`；不再叠加旧基础提示。三档覆盖、充分即止、最多自动五轮、下游材料边界、来源和 gap_updates 规则保留。修正重试仍使用原有重试指令，旧资源保留供兼容。
- **请求诊断**：每次实际 M1 调用（含修正）记录 request/attempt、system/payload/schema UTF-8 字节；完成时记录耗时、输入/输出/思考/正文 tokens 和 finish，失败记录分类与耗时并沿用完整异常证据。日志不输出用户正文或密钥，运行日志仍仅在点击“保存日志”后写盘。

没有降低思考强度、max_tokens 或 timeout，没有删减用户答案、来源或 Schema，没有新增输出截断。该次慢请求使用 max；三协议离线请求体已检查仍保留 max 和 65536 输出预算。

## 验收与边界

30 项本轮新增回归通过。定向和相邻检查按各节点最后一次完成结果合并，300 个不同节点中 296 通过、4 个既有合同差异；用本轮 before 的 M1 模块逐一复现了这 4 个失败，没有改旧测试掩盖差异。最后受影响组 114 项通过。规范与需求两轴复查分别 0 项待修发现。

覆盖等待只读校验 100 次、真实 Web 控制器快照 30 次、截图原问句及重排、普通同义问句、保存恢复、主动补答、两轮重复后的最新答案、同范围不同 gap、手机端/快捷键/两列布局等新范围，以及数量交换和否定词移动。没有增加一个模型来做判重。有限文字规则不能保证识别任意语义改写，提示仍要求模型只澄清上一条答案中的具体不明确处。

这些是离线解析、会话、协议请求体和现有 UI/桥接回归证据，不是本轮真实模型内容质量、服务耗时或新 EXE 证据。完整命令、旧差异和审查闭环见 [验收](../../verification/interview_reliability_20261011/results.md) 与 [双轴审查](../../verification/interview_reliability_20261011/review.md)。
