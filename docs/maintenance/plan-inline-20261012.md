## 目标与现有行为

原方案已存在于会话投影，但 Web 和 Tk 渲染都跳过方案卡，转到顶部面板；确认后的需求表仍重复展示。原流程没有独立的返回位置，若用撤销确认模拟返回，会使下游成果失效并再次请求模型。

本次将原方案面板的完整内容及阅读、编辑、关键工作复核、确认生成、查找 Skill 操作移入对话。删除顶部“核对方案”和单独“修改方案目标”入口；完整方案编辑保留。确认需求后隐藏需求表，返回需求核对时再显示。

## 返回与继续

| 当前阶段 | 返回位置 | 继续行为 |
|---|---|---|
| 需求核对 | 已有目标与访谈问答 | 回到现有需求表，不新增问题 |
| 方案生成或方案核对 | 需求核对开始处 | 恢复已有方案；取消后尚无方案时保留生成入口 |
| Skill | 方案核对 | 恢复已保存的候选与选择 |
| 最终提示词 | 使用 Skill 时返回 Skill，否则返回方案 | 恢复已生成提示词 |

返回和继续只改变核对位置，不撤销确认、不清空回答或成果、不发模型请求。实际编辑仍走原 SessionState 版本失效链，旧方案及提示词保留历史可读，复制与导出受原状态保护。模型运行时返回先使用原 Stop 取消路径；已有作用域、响应关闭和迟到隔离继续生效。

## 状态与呈现

SessionState 推导可达路线，在 control 中保存核对位置及需求、方案、Skill、交付版本依据。旧文件无需改 Schema；保存重开恢复位置，失效或非法位置回到业务当前阶段。只读投影不改变状态或写日志。

Web 返回携带会话、操作标识、阶段及快照，绕过普通命令和草稿等待；Tk 返回按钮也绑定当前内容和操作。普通 Web 命令固定点击时的会话/快照，草稿保存后再次校验，避免旧“继续”命令在返回后的新卡片上生效。返回定位到核对区域开始；方案内容的折叠开关在普通刷新后保留。

Debug 增加阶段导航 INFO（前后阶段、保留成果、零模型请求）和去重的方案内联 DEBUG（会话、版本、状态）；没有逐帧或轮询事件。日志颜色、脱敏、手动完整保存保持原合同。
