# 统一对话工作区：设计讨论

日期：2026-10-09。状态：建议方案，尚未实现，也未将建议视为用户已确认的全部设计。

## 目标与依据

用户希望从需求页对话化扩展为全流程整合：提出目标、回答追问、确认需求、核对方案、选配 Skill、交付提示都在同一处完成。

依据为当前 [交接](../../HANDOFF.md)、[架构](../architecture.md)、[UI 指南](../ui-handoff.md)、[比赛升级规划](../competition/参赛要求核对与展示升级规划-20261008.md)，以及 CodeGraph 提供的当前 `GuidedFlowMixin._build_layout`、`_build_requirements_page`、`_primary_action` 源码。比赛规划的五阶段可以作为同一工作区内的阶段标记，无须对应五个独立页面。

现行代码已具有需求、方案、Skill 和最终交付工作流；对话化可复用这些能力。当前主动作还依赖 Notebook 页面索引，后续需将“当前业务动作”和“切换/定位视图”解耦。对话时间线、事件记录与恢复显示仍需设计，不能声称现有保存会话已经能还原完整聊天界面。

## 推荐布局

- 顶部：任务名称、当前阶段、设置与保存；继续保持设置位于保存左侧。
- 中央：一个连续对话区，包含用户消息、AI 追问、需求摘要、方案、Skill 候选和最终提示卡片。
- 底部：固定多行输入框和发送按钮；在当前消息附近展示确认、修改、跳过、重试等相关操作。
- 侧边：可收起的“当前任务摘要”，显示当前有效的已确认需求、方案状态、所选 Skill 和待补充事项；点击可定位对应卡片。窄窗口改为抽屉，优先保留对话与输入区。
- 模型设置：继续由右上角打开。统一工作区可考虑用面板/弹窗承载表单，保留独立确认、测试连接与修改后重新确认；这只是后续布局建议。

## 各阶段如何出现在对话中

| 阶段 | 用户交互 | 对话呈现与复用能力 |
|---|---|---|
| 描述目标 | 输入任务并发送；类别和整理深度放在输入区附近 | 保留原始目标，调用现有 M1 分析 |
| 澄清需求 | 回答追问、选择完整选项、表示不确定或先跳过 | 显示自然语言问题及 AI 理解，标明建议与用户提供的信息；仍支持 M5 局部示例 |
| 核对需求 | 查看摘要，点击“确认需求”或继续补充 | 摘要卡片引用当前需求版本；确认通过现有会话方法落地 |
| 核对方案 | 阅读/编辑方案，点击确认 | M2 方案卡片含目标、范围、步骤、完成标准和待补充项 |
| 选配 Skill | 选择候选或直接跳过 | 复用本地/联网发现、适配分析与真实绑定操作；显示来源、用途及证据限制 |
| 提示交付 | 查看、复制、导出，或提出新的修改 | 由现有组装/整合流程生成结果卡片；可有展开阅读模式；短文本试运行继续显式触发 |

用户要求中的“程序回复”可先由现有结构化模型结果渲染成自然语言和卡片，不需要为改写展示额外发起模型请求。初版仍使用现有请求/响应方式；真实逐字流式输出属于另一个 API 与解析能力议题。

## 状态、来源与恢复边界

- SessionState 继续作为业务事实源。对话消息记录用于呈现与追溯，不创建另一份独立的需求/方案/Skill 确认状态。
- 消息可关联阶段、问题/需求/方案对象、版本及请求标识；历史卡片显示当时内容，当前摘要从有效业务状态生成。保存格式若增加事件记录，必须兼容旧会话迁移，避免假造旧聊天记录。
- 发送补充、回答某题、编辑方案和确认方案是不同事件。尤其多题追问需要明确答案目标，不能仅凭最近一条消息位置绑定答案，也不能把任意补充覆盖原始目标。
- 确认动作建议通过消息里的明确按钮发起。用户输入内容和模型自行宣称“已确认”均不能绕过现有会话确认条件。
- 需求改变后，旧方案/结果保留为历史并标明依据已变化；旧卡片按钮不得对新版本执行确认、选择或生成。
- 等待模型时显示真实阶段和运行状态；取消、失败、超时可恢复，输入保留。继续保留请求身份、会话/配置版本检查、迟到响应隔离和 Tk 主线程更新。
- AI 规划新增未知显示为待确认建议；一般未决项可随最终提示交付，保留“不确定”“先做草稿”和跳过 Skill 的路径。
- Skill 的选用仅关联下游 AI 使用说明，不表示安装或执行。最终提示生成也不自动执行用户任务。

## 后续实施顺序与完成条件

1. 先制作统一工作区预览，用同一案例展示追问、需求摘要、方案、Skill 和最终提示；覆盖窄窗口及长内容。
2. 提取与页面索引无关的动作判断，增加对话呈现组件；保持现有工作流、业务对象与控件依赖可追踪。
3. 接入消息事件、回复目标和保存恢复；设计旧会话打开时的摘要显示，明确历史内容和当前有效内容。
4. 定向验证正常流程、跳过 Skill、未知项保留、修改后的过期处理、取消/失败重试、保存重开与长对话滚动。真实模型和 EXE 验证独立记录，不以离线结果替代。
