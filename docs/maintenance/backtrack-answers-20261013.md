# 返回上一步：恢复回答与重新推进

## 用户规格与测试边界

回答整轮完成并提交后，返回可立即取消正在进行的模型处理并恢复该轮全部已填文本，题目回到未提交状态。需求核对/确认后返回同一最后回答轮，并暂时隐藏其生成需求/思考段；方案生成/核对返回需求核对的开始位置。Skill阶段返回方案需仍显示“确认方案并查找Skill”和“确认方案并生成提示词”，可再次选择下一步。移除“已核对修改后的关键工作”按钮及其单独门槛，用户仍显式确认整个方案。

沿用本会话已授权公开SessionState/WorkspaceController动作、隔离保存加载、模拟模型和生产DOM边界。先复现确切症状、逐slice红绿；不调用个人API或收费模型。基线为当前未提交工作树副本，不能覆盖此前成果。本轮不提交推送。

## 根因与修复

- 旧返回仅改变浏览位置。回答已离开待答队列，没有整轮快照，无法回到可编辑输入；后续需求和思考也仍显示。现在首次提交前捕获单个有界业务快照，同轮分批共用。返回到回答阶段在副本原子恢复，版本递增、确认与派生成果失效；API运行证据及全部思考记录保留，仅后续思考暂隐藏。
- 单纯重建业务队列仍不够：Web/Tk沿用旧空输入，旧草稿同步可能迟到覆盖。恢复世代改变时清理旧输入缓存、加载完整回答并聚焦首题；旧世代写入被拒绝。返回携带当前未同步输入，不等待排队flush；部分提交后新填写、修改及明确清空均保留，范围限本轮问题。
- 方案操作只对draft状态显示，已确认后返回缺少下一步；原导航位置还可压过新搜索。两个明确确认动作对当前draft/confirmed方案均可用，整体确认处理关键工作复核，不再独立显示“已核对修改后的关键工作”。重新推进退出回看位置，取消搜索保存resume_kind，继续启动原类别的新搜索。
- 旧会话没有快照时优先使用思考记录的history_count恢复完整轮，兼容提交组/旧逐题记录，撤回尾部补充并移除依赖撤回答案的事实、补齐合法题目/gap。换新目标清旧快照，损坏快照不会半恢复；提示保留当前内容及下一步，Debug保留完整异常原因。
