## 4. 当前软件能支撑什么

截至本次核对，最新交付为 `dist/PromptSmith_20261008_skill_handoff/PromptSmith.exe`，构建时间为 2026-10-08 00:31。

已有实现与记录支持的主线：

1. 用户描述任务，AI 结合任务类别与思考档位分析和追问。
2. 用户确认要求并形成初始方案，程序保留状态和来源关系。
3. 可检索本地 Agent Skill，也可继续联网检索并由 AI 分析适配性，用户决定采用哪些。
4. 将所选 Skill 的名称、来源、本地路径或网络链接、关联工作和步骤带入最终提示。
5. 复制、导出、保存与重开，为其他 AI 的后续任务提供可复用交接材料。

Skill 是供 AI Agent 使用的指令资源。网络发现保留 Skill 索引、GitHub 和开放网页三个并行来源，各有 45 秒预算；后续读取与 AI 筛选仍有耗时，所以不能把每来源预算宣传成全过程用时上限。软件提供选择与使用建议，下游 AI 根据提示获取、阅读并应用 Skill。

验证口径：

- 最近一轮 155 项相关检查分批通过，另有编译、发行包资源核对、项目目录与独立目录启动烟测。
- 这些记录主要是离线程序验证，不能当作最新真实模型全链路内容效果或跨电脑兼容性的证据。
- 上一轮 12 项无关历史测试/契约失败单列于 `verification/agent_skill_target_20261007/results.md`；不将现状表述为全部测试已通过。
- 后续准备参赛版时，补充明确缺失的真实案例、用户试用和另一台 Windows 的运行证据；已有通过项仅因新改动、失败证据或需求缺口而重测。

## 5. 如何讲清创新与研究基础

建议围绕三项可演示机制组织创新说明：

| 机制 | 向评审展示的变化 | 需要回答的验证问题 |
|---|---|---|
| 引导用户形成明确要求 | 一个模糊任务经过追问和确认，变成有受众、范围、约束、输出标准的任务资料 | 关键要求是否更完整？有无重复追问、诱导或无依据新增？ |
| 把 Agent Skill 关联到具体工作 | 展示候选的适配理由，用户选择后明确用于方案中哪一步 | 找到的是否确为 Agent Skill？该 Skill 对指定工作有何帮助？ |
| 将协作过程整理为可独立使用的交接 | 在新对话中仅交付最终提示与来源，检查另一 AI 能否理解并执行 | 关键要求、未知项、Skill 来源与用途能否保留？ |

架构、状态维护、版本与来源关联是实现这些机制的技术依据。多模型接入、按钮数量和支持类别数量宜作为配套能力，创新主张应说明具体解决的问题。

已有论文可说明团队研究过提示表达对模型准确率、词元成本和回答结构的影响，并提供控制变量的实验思路。论文指出效果随模型与任务变化，礼貌程度与正确率没有简单的线性关系。需求引导、Skill 整合和跨对话交接的收益，需要本软件的新实验支撑。

对第三方模型、公开 Skill 和开源依赖标明来源、版本及采用范围；自主贡献聚焦于产品机制、软件实现与验证。

## 6. UI 与产品包装建议

目标是让首次接触的评审迅速看懂：正在完成什么任务、已经确认什么、AI 正在做什么、下一步能做什么，以及最终得到什么。

### 信息结构

建议以五个可感知阶段呈现流程：**描述任务 → 澄清需求 → 确认方案 → 选配 Skill → 交付提示**。Skill 为可选增强，用户可以从方案继续交付。

| 页面 | 主要内容 | 建议的交互与视觉重点 |
|---|---|---|
| 描述任务 | 任务输入、类别、思考深度、最近项目 | 简短定位语、少量场景示例、明确的开始入口 |
| 澄清需求 | 完整问题与选项、用户回答、已确认要求 | 问题内容集中展示；重要要求可核对；显示正在分析或等待回答 |
| 确认方案 | 目标、范围、关键工作、执行步骤、输出标准 | 结构化方案卡片，可直接编辑；修改后的状态清楚可见 |
| 选配 Skill | 本地/联网发现、AI 筛选、候选与已选内容 | 候选卡片展示名称、用途、匹配理由、来源和选中状态；长内容可展开 |
| 交付提示 | 可直接复制的提示、Skill 使用说明、后续补充项 | 清晰的成品预览与复制/导出入口，支持回到对应内容修改 |

通用改版要点：

- 一屏突出当前主要操作，把低频设置和诊断详情收拢；返回、编辑、重试有稳定位置。
- 后台过程展示真实阶段、已用时间、当前结果和可执行操作；任务完成、空结果、部分结果、失败分别表达，避免没有反馈的静止界面。
- 将内部模块名、契约字段和原始 ID 放入详情；主界面使用用户能理解的工作名称。
- 核心问题在澄清阶段尽量完成；后续信息不足作为最终提示中的补充项清楚呈现，延续已确定的交付机制。
- 处理长中文、长链接、窗口缩放、键盘操作、焦点顺序和高 DPI，确保按钮与内容始终可读。

### 视觉方向

建议先制作一套“清晰、专业的 AI 工作台”预览：浅色主画布、深色导航、蓝青色重点、少量状态色；使用统一的字体层级、间距、卡片、图标和按钮规则。状态同时配文字，录屏缩小后仍能识别。

保留 PromptSmith 名称；产品图标、应用首页、技术文档封面、PPT、演示片头和导出文件沿用同一视觉语言。先比较关键页面预览，再落实组件与实现方式；技术选型由布局与交互需求决定。

UI 完成条件：首次用户能理解流程并找到下一步；完整问题和候选可读可选；各类加载/完成状态有反馈；最终提示易于核对和复制；目标分辨率与缩放下无关键裁切；至少用一条真实案例验证全过程。

## 7. 技术文档与视觉素材怎么组织

建议维护以下四组内容，使用同一个版本与案例编号：

1. **技术方案主文**：产品问题与定位、整体架构、AI 机制、功能设计、开发测试、部署、应用价值、限制与展望，最终套用官方模板。
2. **软件说明与部署资料**：运行环境、模型配置、五阶段操作、示例任务、保存导出、常见问题；说明桌面端与远程模型的关系。
3. **测试与效果报告**：功能用例、兼容性、异常恢复、真实模型链路、对照实验、用户试用，逐项标明版本、环境、输入、结果和证据位置。
4. **图与案例素材**：系统架构图、用户流程图、AI 与程序职责图、Skill 搜索与整合图、真实界面截图、案例前后对照、试用结果图。

技术图与产品页面采用一致术语。每张图解释一个关键结论，每个效果结论能追溯到记录。制作顺序上先稳定 UI 和展示案例，再集中截图与排版，减少素材返工。

## 8. 答辩与视频的演示主线

建议采用“一个实际任务贯穿”的叙事。例如用户此前提出的分部积分讲解任务：最初只说“讲解分部积分法”，随后确认学习基础、语言风格、讲解长度、例题与练习要求；形成方案，选用实际找到且适配的 Agent Skill，再将最终提示交给下游 AI，展示能核对要求的输出片段。

只有在真实预演成功后才把该任务确定为主案例。真实搜索无适配项时如实展示结果；不编造 Skill。可另外准备写作或软件规划案例作补充，说明产品的跨任务适配。

视频建议按约 4 分钟组织，属于制作建议：

| 时间 | 画面与要点 |
|---|---|
| 0:00–0:25 | 实际痛点与原始模糊任务 |
| 0:25–1:15 | 关键追问、用户回答和明确要求 |
| 1:15–1:50 | 可执行方案与关键工作 |
| 1:50–2:35 | Skill 候选、适配理由、用户选用及用途 |
| 2:35–3:25 | 最终提示交给另一 AI 后的实际结果及要求核对 |
| 3:25–4:00 | 核心机制、真实测试/试用结果、应用前景 |

录屏中的实时操作和历史结果回放分别标注；删去等待时间时给出说明。现场备份使用同版 EXE、已保存案例和录屏，便于网络异常时继续说明真实功能。

答辩 PPT 建议先按约 10–12 页规划：痛点与用户、产品定位、完整流程、关键交互、机制创新、系统架构、Skill 整合、效果证据、应用案例、当前限制与未来规划。实际页数和节奏需匹配后续确认的答辩时长，规则文件未给出固定页数。

应提前准备能用证据回答的五类问题：与直接使用聊天模型有何差异；自主实现了什么；为什么采用这些模型与机制；如何证明使用效果；Skill 或网络不可用时如何继续。

## 9. 效果证据的补齐方案

沿用历史方案中“先固定评价标准，再对照”的思路，规模根据剩余时间与额度调整：

- 正式案例可按六类任务各 2 个准备，共 12 个；这是团队建议规模，不是官方数量要求，也不等于已完成实验。
- 至少区分原始输入、普通改写、本产品流程；加上含同样已确认事实的普通表达条件，才能判断收益来自信息补充还是组织机制。若强调优于已有访谈方法，应加入对应固定版本基线。
- 单独比较有/无 Skill 时，保持要求、初始方案和下游模型一致，计入搜索与整合成本；不能把完整流程的收益全部归因于 Skill。
- 观察关键要求覆盖、硬约束违反、无依据新增、结果可用性、后续修改次数和流程失败；同时记录用户操作时间、等待时间、调用与词元总成本。
- 在新对话中仅提供导出材料，检查能否恢复任务、约束、未知项和 Skill 用途，直接验证“交给其他 AI 使用”的核心目标。
- 邀请 3–5 名非开发成员试用属于可行的初步建议，用于发现操作困难和具体价值；保留失败和负面反馈，不以小样本作普遍效果结论。

正式记录应固定软件、模型和 Skill 版本，保留输入、实际回答、输出、评分准则与耗时。评阅尽可能隐藏实验条件并由两人核对分歧。先用少量调试案例估算成本，再开始正式采集。
