# 比赛、包装与答辩资料

供三人共同制作技术文档、UI 展示、答辩 PPT 和软件演示/宣传视频使用。当前分工为两人功能、一人 UI；后续共同完成展示材料。

## 阅读顺序

1. [参赛要求核对与展示升级规划](参赛要求核对与展示升级规划_20261008.md)：当前评分、材料清单、UI 方向、视频主线和后续完成条件。
2. [比赛原始规则](<sources/JSAI2025 (1).pdf>)：正文为 2026 年，PDF 实际第 3 页是提交规范，第 4 页是赛题二，第 5 页是评分。
3. [产品历史参赛方案](需求引导式提示构建助手_参赛方案最终稿.md)：产品动机和评测思路；其中成员分工、日期、计划状态以当前交接为准。
4. [研究论文](sources/202608V14N5_13.pdf)：研究基础；不能将论文的提示语气实验结果写成本软件需求引导/Skill 功能的效果。
5. [当前架构](../architecture.md)、[UI 指南](../ui-handoff.md)、[验证资料](../../verification/README.md)：为技术图、截图和结论提供事实依据。

## 官方要求摘要

创新性 20、技术实现 20、功能完整性 20、方案完整性 20、应用价值 15、总结与展望 5。桌面软件包符合赛题范围。UI 美观支持体验与表达，没有独立美观分。

作品名 ≤20 字、简介 ≤300 字；技术方案参照官方模板，PDF ≤10M；视频 MP4、3–5 分钟、≤300MB；PPT 转 PDF；佐证合成一个 PDF。材料不得出现学校名称、校徽及指导教师信息。详细命名与网盘要求见原规则。

## 材料生产清单

| 产出 | 主要内容 | 建议牵头与配合 |
|---|---|---|
| UI 视觉规范与页面 | 信息结构、组件、状态、完整流程 | UI 牵头，功能队员核对事件/状态 |
| 技术方案 | 需求、架构、AI 机制、实现、测试、部署 | 功能队员供事实，三人统一叙事与图表 |
| 测试/效果材料 | 真实案例、对照数据、用户试用、限制 | 功能队员组织，UI 队员参与易用性观察 |
| 答辩 PPT | 问题、机制、演示、技术、效果、前景 | 三人确定内容，UI 队员统一视觉 |
| 软件视频 | 真实操作、剪辑、旁白、结果 | 三人脚本与录制，统一版本后制作 |
| 提交文件包 | 成稿、佐证、软件、说明、代码链接 | 管理员核对，三人交叉复查 |

以上为待执行清单，不代表文件已制作。后续可在本目录按 `ui/`、`technical/`、`slides/`、`video/`、`evidence/` 建子目录，只有产生实际文件时再创建。

大体积录屏原素材与视频通过团队存储共享，索引里记录版本与链接，避免把多轮素材全部放进 Git 历史。正式提交按赛事要求组织。

## 展示纪律与待确认项

演示使用同版软件和真实案例，历史回放明确标注。效果数字可追溯，来源/授权说明完整。论文首页含单位等信息，提交前核实佐证匿名处理方式，保留原件。

尚待取得官方模板正文、截止时间、答辩时长/页数要求和最新通知。团队编号、最终作品名待打包前落实。它们不妨碍先开展 UI 和案例设计。
