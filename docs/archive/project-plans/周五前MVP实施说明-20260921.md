## 确定的流程

输入任务 → 类别与关键追问 → 编辑并确认需求卡 → 生成完整初始方案 → 用户确认方案 → 识别关键工作 → 检索与选择 Skill → 整合最终方案与提示 → 保存导出。

六类任务为写作、PPT、学习、策划、数据分析、编程，另有通用入口。类别只帮助确定应问的内容，不能代替用户选择 Skill。基础方案组织由程序和模型完成，不再设置“选择方法包”。

“完整初始方案”至少包含目标、已确认要求、步骤、交付物、完成标准和未决事项。它可以不依赖任何 Skill 使用。Skill 阶段只补充具体工作的方法与执行条件，用户可全部跳过。

## 周四必须跑通

| 功能 | 验收 |
|---|---|
| 六类与通用入口 | 每类有实际字段配置，支持直接描述及手动改选；未验证类别明确标记 |
| 真实 AI 引导 | 接通一个真实API，提取已有信息并追问关键缺口，确认与建议分开 |
| 可编辑需求卡 | 修改和确认生效，未知信息保留，不把推荐默认当作用户答案 |
| 完整初始方案 | 未检索Skill之前能够生成、修改并确认方案 |
| 末端目录检索 | 从方案关键工作匹配真实记录，展示来源、用途、环境与未验证状态；无匹配可跳过 |
| Skill整合 | 用户选择后更新对应步骤，展示改动；保留原方案，不把新功能变成既定要求 |
| 最终提示 | 可复制，中性／适度礼貌只改变措辞；依赖外部宿主的步骤单独说明 |
| 保存与导出 | JSON会话保存重开，Markdown导出包含需求、初始方案、来源、最终方案和未决事项 |
| Windows发行目录 | exe连同依赖文件交付，在另一台未装Python的Windows电脑检查启动、保存及联网调用 |

方案未确认时不启动Skill推荐。需求或初始方案变化后，旧推荐和最终方案标为需要重生成；用户取消某项Skill时重新整合，不能留下已取消条目的指令。

## Python 实现建议

采用 Tkinter/ttk 界面、JSON 会话与类别配置、一个 API 适配模块、PyInstaller 目录模式。论文代码目前无法取得，不作为依赖；A直接新建模型调用、结构化校验和日志模块。桌面程序调用API时使用后台线程，通过队列回传界面，设置超时与错误提示；失败保留输入，不自动冒充成功。

建议模块划分：

| 模块 | 职责 |
|---|---|
| app / ui | 四步界面、用户确认、加载与导出入口 |
| workflow | 需求、初始方案确认、Skill选择、最终整合的状态与失效规则 |
| model_client | 单模型接口、结构化结果校验、超时及用量记录 |
| categories | 六类与通用字段、提问依赖、检查要点 |
| skill_catalog | 真实目录记录、标签匹配、无匹配结果；模型只能重排真实候选 |
| storage / export | 会话JSON与独立可读的Markdown |

记录至少包含：任务和类别、字段及来源/状态、初始方案版本与确认状态、关键工作、候选Skill及匹配理由、选中项、最终方案、语气、运行记录。密钥不进入会话、日志和导出。初版可由团队成员配置个人API密钥并仅在会话内使用；统一团队密钥需经服务端转发，不能塞进exe。

目录记录包括名称、真实来源、版本或核验日期、适用工作、输入输出、宿主和工具依赖、许可、核验状态。现有研究记录偏向需求澄清与规划，不能假设已有PPT制作、绘图等完整能力。只有来源已核验的条目进入目录；没有适合项就返回空结果。该功能在界面命名为“在已核验目录中查找”，不称为实时全网搜索。

在最终文档中写清每个Skill对应的步骤、所需材料、输出、运行前提和来源。可复制的方法说明与必须在特定宿主运行的能力分开表述；本程序不自动下载、安装或执行外部指令。

## 打包与交付

Python源码先跑通，再由PyInstaller在Windows上构建发行目录。以下命令是拟议构建方式，须在入口和资源路径实际存在后调整验证：

```powershell
python -m PyInstaller --noconfirm --windowed --onedir --name PromptGuide --add-data "config;config" app.py
```

交付整个发行文件夹，不能只复制exe。配置读取兼容打包资源路径，用户会话保存到可写目录。首次最小打包应在9月22日完成，避免9月24日才发现依赖缺失。单文件exe可后续优化；exe并不包含云端大模型，AI功能仍需网络、账户与额度。

交付包包含发行目录、源码、锁定的依赖、运行说明、模型配置说明和已知问题。打包失败时提供源码启动方式便于继续工作，但 Windows 打包验收仍应记为未通过，不将降级等同于完成。
