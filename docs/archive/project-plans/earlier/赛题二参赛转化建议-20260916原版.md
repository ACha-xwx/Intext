**参赛建议：将提示词研究转成可操作的对照实验软件。**

整理日期：2026-09-16。依据当前提供的两份 PDF，以及团队“三个人，实验代码和数据保留”的补充。本文件是内部讨论与执行建议，不是已完成软件的技术报告，也不是最终参赛提交稿。

最值得保留的方向是：做一个“提示词实验台”，首个应用场景选中文提示工程教学，帮助教师、学生完成提示词对照实验，查看准确率、词元消耗和显性回答结构，并保存可复现的结果。三周内的目标是交付一个核心流程完整的小软件，以及真实测试、初步试用和参赛材料。是否能完成取决于前两天的代码复跑与部署验证，不能仅凭代码存在就确认工期。

**你们并非从纯理论起步。** 论文是一项有数据、有调用流程、有分析脚本的实证研究。论文图 1 已经包含输入层、处理层、分析层，接近软件模块的雏形。下一步是让另一个人无需修改实验脚本，也能提交自己的题目、运行实验、核对结果并导出报告。

研究回答的是“语气在这组实验中造成什么差异”；软件帮助用户回答“在我选择的题目、模型和模板下，差异是什么，依据是否足够，下一次应该采用哪种配置”。

依据文件：

- [提示词语气对国产大语言模型输出结果的影响分析](<../../../competition/sources/202608V14N5-13.pdf>)，以下称“论文”。共 8 页，刊物页码 71—78。
- [算法创新赛竞赛规则](<../../../competition/sources/JSAI2025-1.pdf>)，以下称“规则”。正文为 2026 第八届；共 7 个 PDF 页面，印刷页码为 1、2、3、7、8、9、10。以下引用均使用 PDF 实际页码。

本次完整读取两份 PDF，目视核对比赛提交要求、赛题二要求、评分表及论文方法与结果图。尚未检查实验代码、原始日志、模型账户或报名系统，也没有外部核验论文参考文献及同类产品现状。涉及产品设计、进度和人数的内容均为建议；论文数据均为论文报告值。

**赛题二允许这类工具，但要求完成软件。**

规则第 4 页将“基础通用（算力、算法、数据相关软件和工具）”“智能分析系统”“桌面/Web/移动端 AI 应用程序”等列入范围，开发语言、平台和场景不限。因此，提示词评测工具在方向上有明确依据，不需要另造医疗、金融等行业背景。

同页要求“已完成开发的软件产品”“完整的核心功能模块”，并要求算法与功能高度契合。论文、静态图表网站或只能由作者手动运行的零散脚本，不足以替代这部分交付。规则没有要求必须自己训练大模型，也没有禁止第三方 API；需如实说明模型来源、开源依赖与自主实现部分，满足合法授权和原创要求。

| 规则要求 | 建议交付的具体证据 |
|---|---|
| 完整核心功能 | 导入题目→配置模板→真实调用→自动判分→核对差异→导出报告，全程可操作 |
| AI 与功能高度契合 | 模型推理是对照实验的必要执行环节，结果进入评测、逐题核验与模板选用流程 |
| 开发测试部署 | 可运行代码、环境依赖、安装说明、测试用例与实际结果 |
| 易用性和兼容性 | 用另一台电脑或干净环境验证安装；请非开发成员独立操作 |
| 创新与差异化 | 说明中文客观题控制变量实验、质量与词元联合观察、逐题追溯的组合价值，并做同类工具核验 |
| 应用价值 | 真实目标用户的任务完成率、用时、问题记录与改进案例 |

这一解释支持选题可行性，不等于保证评委对创新性或 AI 融合程度给出高分。特别是“批量调用、图表和报表”本身需要用场景与差异化证据来支撑。

**把已有成果逐项变成用户功能。**

| 论文中已有的研究资产 | 用户能够使用的软件能力 | 证据与边界 |
|---|---|---|
| 635 道清洗后的浙江卷纯文本选择题 | 示例数据集、题目导入、标准答案判分 | 论文第 5 页；新增导入先限定为有标准答案的纯文本单选题 |
| 五档语气及感知检验 | 预置五档模板，显示固定题干与可变语气，运行前预览完整提示词 | 第 3—5 页；固定模板的验证不等于任意自动改写都只改变语气 |
| 三模型批量运行、重复、异常日志 | 模型适配、进度、失败重跑、结果保存 | 第 5 页；当前接口能否继续使用需复跑确认 |
| 准确率、词元与相对中性语气比较 | 结果比较页，同时展示正误、资源消耗、有效响应率 | 第 4、6 页；词元与账单费用不可直接等同 |
| 显性回答结构规则 | 查看同题回答，对片段作规则辅助标注 | 第 4、7 页；不是模型真实思维或推理质量评分 |
| 28,575 条正式记录 | 历史实验案例、功能校验样本、可追溯演示数据 | 第 5 页；635×5×3×3，不是 28,575 道独立题目 |

软件介绍可以使用下面的定位句：

> 提示词实验台是一款面向中文提示工程教学的对照实验软件，帮助师生在固定题目与模型配置下比较提示词表达，核验准确率、词元用量与显性回答差异，并保存可复现的实验结果。

这是拟议定位，软件完成前不应作为“已经实现上述功能”的成果声明。

**推荐一个主方向，保留两个备选。**

| 方向 | 谁会使用、解决什么问题 | 三周判断 |
|---|---|---|
| 提示词对照实验台（推荐） | 提示工程课程师生：免去手工组织对照、抄结果、汇总数据的工作 | 与论文方法和数据最贴近；先找两名目标用户核实需求 |
| 提示模板回归测试工具 | 小型 AI 应用开发团队：修改模板后检查固定任务集的正误、消耗和失败情况 | 软件工程价值明确，但需要真实开发需求与独立业务样本；可作为后续方向 |
| AI 素养交互实验软件 | 教师带领学生先预测、再运行实验、解释证据 | 易形成课堂流程；仍需支持真实实验，不能只展示论文图表 |

三周内选择一种目标用户，避免同时承诺教师、企业、学生个人和所有行业。若找不到教学试用对象，可以先服务本团队及其他研究小组的实验复现工作，直接记录实际需求；不要虚构课堂应用。

**最小版本只保留六个核心模块。**

1. 数据导入：CSV 一种格式即可；题目、选项、标准答案为必要字段，学科为可选字段。提供示例文件与清晰的错误提示。
2. 实验配置：预置五档语气，中性作为基线；选择模型、重复次数及题目子集，预览完整提示词与计划请求数。先确保一个模型可实时运行，第二个模型在第一周闭环稳定后接入。
3. 实验执行：显示完成数、失败数和进度，逐条保存结果，支持失败重跑及中断后继续。设置合理的请求上限与并发，不能机械照搬论文中的 25 并发和 900 秒超时。
4. 结果比较：准确率、有效响应率、原始词元用量和耗时；清楚展示每个指标的分母。准确率建议同时报告“计划作答中成功且正确的比例”和“成功解析作答中的正确率”，拒答、超时、解析失败单列。
5. 逐题核验：并排展示同题各模板的原始回答、提取答案和判分；保留请求配置。结构着色在现有脚本易于接入时加入，注明规则辅助标注，不能影响基本判分和核验流程。
6. 导出与选用：导出结果表、简短实验报告和用户选定的模板配置。报告包含数据集、模型版本、日期、参数、样本量、失败情况和解释边界；证据不足时允许不推荐任何模板。

若原实验代码是 Python，且团队没有现成前端，可优先考虑 Streamlit + 原实验模块 + SQLite/文件存储。若已有熟悉且可复用的 Web 框架，则沿用。无需为参赛另建复杂前后端、账号权限或云基础设施。提供评审能验证的部署方式，优先保证清晰安装包或代码包与本地启动指引；在线演示地址是可选便利，不是原规则中的强制唯一形式。

本轮不纳入训练/微调模型、RAG、任意开放问题自动评分、多智能体、浏览器插件、多租户管理、自动搜索所有提示词。它们会拉长工期，对现有主线没有必要性。

**论文支持评测能力，尚不支持承诺普遍优化收益。**

论文第 6 页报告，礼貌语气相对中性的准确率变化为 DeepSeek +0.157、Doubao +0.000、Qwen +0.420 个百分点，明确指出尚不能认为存在统计显著优势。产品不宜命名为“保证提高准确率的提示词优化器”，也不应宣称“越礼貌越好”。

同页报告 DeepSeek 粗鲁语气的总词元比中性增加约 12.8%，其他模型变化方向不同。这能作为“为什么需要按任务实测”的历史案例，不能直接变成软件“普遍节省 12.8% 费用”的宣传。增幅与节省比例的分母不同，词元与实际收费也不同。

论文第 4 页结构脚本在校正规则所用的 240 条片段上，与共识标签一致率为 77.92%。它是规则辅助标注的内部核对结果，不是独立测试集上的泛化准确率。第 7 页说明结构结果针对显性回答，不包括单独保存的推理文本；结构篇幅不代表真实思维、推理质量或无效消耗。

软件首版给描述性比较即可。如果后续要声称选出更好的模板，应当用一组题做选择，再用另一组未参与选择的题验证；不能在同一组题上选赢家后，又用这组题证明提升。重复作答不是独立题目，若估计不确定性，应以题目为配对与聚类单位。按历史错误筛选出的困难题可用于探索性分析，不能替代独立验证集。

模型接口的输入、输出、推理与缓存用量可能包含重叠关系；推理词元可能已计入输出。保存原始 usage 并注明口径，避免重复相加。只有取得适用费率和计费规则后才展示“估算费用”，同时标注费率日期；否则只展示词元消耗。

**三人三周的安排，按交付物验收。** 当前文件没有明确截止日期，以下使用相对天数；应先在报名系统核实真正的提交时点，再倒排材料准备和上传。

| 时间 | 要完成的结果 | 验收方式 |
|---|---|---|
| 第 1—2 天 | 盘点代码、依赖、题库、模板、日志；一个模型、两模板、10 道题的小实验；访谈两名目标用户 | 能拿到答案与用量，打开一页对照结果；确认哪个模块可直接复用 |
| 第 3—7 天 | 六模块的最简闭环，先一个实时模型；完成一次同类工具小范围核验 | 非后端成员能导入→运行→查看→导出；不靠作者手改文件 |
| 第 8—10 天 | 五档模板完整支持，比较页、逐题查看、失败恢复和历史导入稳定；有余力再完成第二个实时模型 | 历史统计与原脚本核对，异常不会静默丢失 |
| 第 11—14 天 | 新增小型实验，5—8 位目标用户初步试用，整理缺陷并修复；第 14 天冻结功能 | 留存任务用时、完成率、反馈和修改前后记录 |
| 第 15—17 天 | 在干净环境安装验证；完成说明、算法说明、测试报告、技术方案和答辩材料初稿 | 另一名成员按文档从零启动；完整走查提交清单 |
| 第 18—19 天 | 录制 3—5 分钟视频，校验匿名与格式，完成一次上传预检 | 视频播放、PDF 打开、分享链接和压缩包全部可用 |
| 第 20—21 天 | 修复阻塞问题、最终提交与备份；不再加功能 | 核实系统提交状态，保留回执与最终材料版本 |

| 负责人 | 持续负责的任务 |
|---|---|
| A：实验与后端 | 模型接口、参数、批处理、日志、答案提取、失败恢复 |
| B：界面与交付 | 页面流程、导入校验、结果展示、导出、安装与部署 |
| C：数据与验证 | 数据核对、指标复算、用例、真实试用、参赛材料；从第一周参与 |

三人共同确定口径，每两天交叉跑一次最新软件。C 不应到最后几天才加入；材料可以从第一周积累，但结果数值必须来自真实测试。

降级规则：第 2 天接口或代码仍未跑通，马上收缩到一个可用模型并优先修复运行链路；第 7 天流程未闭合，砍掉结构着色、自定义模板和第二个模型；第 14 天冻结后只处理缺陷、交付与材料。只有历史结果浏览、无法运行新任务的软件不足以支撑本方案承诺的核心功能。

**补做的证据以“软件确实有用”为中心。**

先做统计一致性检查：选取一份固定历史子集，核对导入条数、答案提取、正确数、用量汇总和原分析脚本是否一致。针对缺字段、非法答案、接口失败、超时、重复重试、中断恢复和导出后重开设计少量有实际意义的测试；记录真实结果。

再做一组新任务。例如 20 道独立准备且答案人工核验的单选题 × 5 档语气 × 2 个模型 × 1 次重复，共 200 次调用；只有一个模型时是 100 次。先少量测量实际耗时与词元，再决定预算和批量规模。这组实验验证软件可以处理新数据，不用于证明微小准确率提升；无需重新跑完论文 28,575 条记录。

请 5—8 位目标用户实际完成“导入 10 道题、比较模板、找到一个具体差异、导出报告”的任务。记录完成率、操作用时、出错点、需要帮助的次数。若与手工/原脚本比较，要使用相同规模和条件，尽量平衡操作顺序，区分主动操作时间与 API 等待时间。报告为小规模初步试用，不能外推为教学效果普遍提升。

创新性需要单独核实。第一周选择 2—3 个真实同类工具，阅读其当前官方说明或实际试用，比较目标用户、控制变量支持、结果追溯、使用门槛和可复现导出，保留日期和来源。此处尚未完成竞品调查，因此不要写“国内首创”“唯一支持”或臆造竞品缺点。若没有独有功能，仍可诚实说明针对中文提示工程教学的流程整合与体验改进。

**按评分分配精力。** 规则第 5 页：创新性 20、技术实现 20、功能完整性 20、方案完整性 20、应用价值 15、总结与展望 5。后三周应优先保证技术实现、功能完整性和方案完整性对应的 60 分所要求的证据，同时用一条可核验的差异化主线与真实试用支撑创新和价值。权重分析不构成分数或获奖预测。

**建议用约 4 分钟演示一个完整用户任务。**

| 时间 | 展示内容 |
|---|---|
| 0:00—0:30 | 谁需要比较提示词，手工实验中有什么实际困难 |
| 0:30—1:10 | 导入少量题，选择模板，预览控制变量和模型配置 |
| 1:10—1:50 | 发起少量真实请求，展示进度、完成结果与失败处理入口 |
| 1:50—2:50 | 加载明确标注的已完成实验，比较正误、词元和具体回答 |
| 2:50—3:30 | 展示规则辅助结构标注（如已实现），选用模板并导出报告 |
| 3:30—4:00 | 展示真实试用反馈、测试结果和适用边界 |

历史记录标“历史实验”，实时请求标当前模型版本与日期；如视频剪掉等待时间，应明示。演示不必等待数百次 API 返回，但需要能够验证真实执行链路。论文中的高考题可能已进入模型训练材料，历史准确率不能当成当前模型泛化能力证明。
