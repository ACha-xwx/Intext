# M1 v0.10：一次回答包含多项信息

本轮真实走查中，用户回答“数值分析里面的，就是学生学习的讲解，做成学生学习讲义”。M1 完整返回 JSON，用同一条回答分别部分澄清领域、确定讲义形式；旧校验只允许一条回答更新原问题对应的一个缺口，因而拒绝整个响应。原失败请求、输出与校验保留在 `verification/guided_flow_20261001/visible_real/calls/`。

## 接口与边界

- 首轮提示 `M1_system_v0.10.txt`，增量提示 `M1_incremental_v0.3.txt`；输入 Schema 为 `M1_input_v0.4.schema.json`，输出沿用 `M1_output_v0.3.schema.json`，外层版本仍为兼容扩展 `m1.v0.2`。旧文件不覆盖。
- UI 提交自由回答时，由程序记录 `context_gap_ids`，只包含提交时已有的未知事项。模型不能自行扩大这个范围；出现在列表中也不表示用户已经回答了它。
- 同一回答可以对列表内不同的未知提出更新，每项仍需引用该回答的真实来源及逐字原文。每个缺口每轮最多更新一次；不存在的缺口、虚构原话、重复更新、过期回答继续拒绝。
- `assessed_gap_ids` 保留逐项处理记录；仅更新附带事项时，不把原问题的回答提前标为已处理。完整审计仍在 `gap_update_history`。
- 没有 `context_gap_ids` 的旧回答继续遵守原有单缺口校验，不静默改变旧实验的含义；旧会话仍可打开和补充。
- 不修改输出预算、120 秒超时、错误分类、失败保留、主动重试、冲突保护或确认权限。

## 证据边界

新增 `tests/test_guided_multi_gap_answer.py` 验证多事项处理、旧行为、越界拒绝和保存重开。原真实响应另以新程序上下文元数据离线回放，见 `verification/guided_flow_20261001/real_response_offline_replay.json`；这是离线兼容验证，不能替代修复后再次真实调用。最终结果见本轮交接报告。
