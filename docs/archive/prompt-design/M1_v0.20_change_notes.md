# M1 v0.20 改动说明

这次把“模型判断”和“程序推进”接得更紧，解决模型已经知道信息不够、程序却把流程卡住的问题。

- 新增 `model_judgment` 的兼容归一化。旧模型没有返回这个字段时，程序根据已有缺口和下一步建议补一个保守判断，不改变用户需求和状态。
- 增加一致性检查。模型判断仍需继续追问时，不能同时把下一步写成需求复核；模型判断不再继续时，也不能继续要求追问。发现矛盾会让模型自动修正，不会把矛盾内容交给用户。
- 合法 JSON 的 `input_error` 统一作为语义恢复信号处理。简称不明、回答含糊和信息不足会保留在访谈中继续核对；JSON 损坏、契约错误、网络/API 错误仍按技术失败处理。
- 新增 v0.20 全量提示补充和 v0.13 增量提示，保留 v0.19 资源，便于回滚和对照。

本轮自动化验证覆盖了 JGS 类术语、旧轮数为零、旧响应缺判断字段、重复语义型 input_error 四条路径。它们是离线合成模型响应测试，尚未等同于真实模型在所有任务中的稳定表现；真实模型效果仍需用实际 API 做一次编程任务和一次非编程任务验证。
