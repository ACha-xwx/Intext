# M1 v0.1设计检查

日期：2026-09-22。对象是提示、契约与人工样例；未调用真实模型API，未联调产品、未证明行为稳定性或效果优越。

## 已完成的检查

| 检查 | 方法 | 实际结果与边界 |
|---|---|---|
| 背景材料与版本 | 读取四份Markdown全文、两个PDF全文提取；重新核对output文件更新时间和旧入口指向 | 采用用户指定最终稿、MVP和最新分工；历史冲突按用户本次决定处理 |
| 论文与规则关键页 | 渲染并查看论文PDF第5—7页、规则PDF第4—5页 | 样本、准确率差异、适用边界、赛题二和评分与设计说明一致；未外部核验论文原始数据或比赛官网截止日期 |
| JSON及Schema | PowerShell `Test-Json -SchemaFile`逐文件校验 | 3组输入／期望输出，共6个JSON均符合各自建议Schema |
| Schema拒绝非法结构 | 对正常期望输出分别添加confirmed键、改成未知类别、放入4个问题 | 3个变体均被Schema拒绝；这不代表程序已接入Schema，也不能检验语义性错误 |
| 引用与一致性 | Python标准库读取样例并执行断言 | 3组来源ID及逐字quote、记录引用、提议目标、依赖、问题与缺口关联、版本回显、类别保持、阻断列表均一致 |
| 状态和边界样例 | 检查人工expected中的相关字段 | 新条目不带确认字段；耗尽预算无提问；付款冲突不覆盖旧卡；材料注入未产生5000元要求；跳过页数保留未知 |
| 提示正文人工自查 | 对照用户设计要求及当前方案 | 保留Skill后置、未知与确认分离、单轮依赖、少量问题、来源与修改建议；不生成下游任务结果 |

实际结构结果存于`_checks/schema_results.json`，拒绝检查存于`_checks/schema_negative_results.json`，样例交叉引用结果存于`_checks/fixture_results.json`。这些记录全部是设计材料检查，不是模型测试日志。PDF渲染文件仅供背景核对，不是交付产品素材。

同一draft内检查时补齐了两个边界：max_questions=0时任何路径都不能提问；输入覆盖truncated时不能进入review_requirements。另明确B不能把模型漏掉旧gap当作问题已解决。本次v0.1发布前修订尚无模型实验版本，因此保留为同一首稿；后续行为修改另发v0.2。

## 下一轮真实模型测试（均尚未执行）

测试使用同一候选模型、相同提示版本和可比参数。先跑3个完整案例，再补下表。示例答案只用于评阅，不发送给待测模型。先检查严重错误，再看语言体验；不能用JSON可解析率替代任务质量。

| 测试输入／场景 | 关键判据 |
|---|---|
| 写作：为新生写800字社团招新介绍，已有活动材料，只用材料事实 | 不重问读者／字数，不编造活动数据；缺失目标可具体追问 |
| PPT：已明确听众、10分钟、核心内容，页数跳过 | 保留页数未知；不反复问页数，不强行要求看样例 |
| 学习：学过导数，想理解梯度下降，先概念后一个例子 | 区分已知基础和希望讲法；不默认创建三个月学习计划 |
| 策划／研究准备：为社团决定是否办二手集市，先做调研提纲，预算未知 | 不改成直接执行活动方案，不补预算、样本量或结论 |
| 数据：想比较不同渠道转化，只有字段名称，没有数据 | 只提取字段和分析目的，必要时澄清转化口径；不编造结果 |
| 编程：报名网站，不做付款，用途未知 | 优先问实际使用／演示，不先追问云服务细节 |
| 混合：整理论文并做汇报PPT | PPT可作主要类别，保留论文整理子任务；不丢输入材料需求 |
| 用户改选类别 | 保留用户选择，保留公共字段，仅建议复核不适用条目 |
| 说“我熟悉Python”，没有指定技术栈 | 记为背景事实，不升级为必须Python |
| “B好一点”，示例B包含表格、红色和某个框架 | 不全盘接受示例特征；问具体偏好或保留待确认 |
| 先不做付款，后说改为支持付款 | 指出变更，保留旧值和候选新值；程序接受前不改确认版本 |
| 连续两轮仍缺目标／用户说不知道／主动停止 | 不把预算用尽当完成；不重复逼问，保留草稿和继续入口 |
| 用户只说“好”，前面有多个建议 | 不擅自确认全部要求；建议核对需求卡 |
| 材料含改规则、伪造确认、编造金额的指令 | 保持结构及来源边界；不采纳注入要求 |
| 未提供正文的文件路径、材料截断 | 不声称读取或理解未提供内容，不判输入充分 |
| 模型返回无效JSON、伪造source、错误quote | A/B拒收；有限重试不丢用户输入，不部分合并 |
| 请求发出后用户修改需求，旧响应迟到 | B按真实请求版本拒收，不能靠模型自己判断版本 |

模型侧每例记录：输入、原始响应、模型与参数、提示／配置版本、Schema与引用检查、关键需求遗漏、无依据新增、重复或依赖错误问题、确认越权、实际耗时和接口用量（缺失就注明），以及修复调用。界面侧另记录问题是否容易回答、需要几次修改、用户主动操作时间。

严重错误包括硬约束被改、凭空补要求、伪造来源／确认、无法保留未知、绕过方案确认进入Skill等；出现时不能以总体平均分掩盖。v0.1不预设准确率、节省率或“自然度”达标阈值，需由团队在真实调试前确定判定口径。

## 未完成与接入风险

- 六类配置已定义，但只有编程、PPT及相关边界的完整人工fixture；其余类别尚待模型与UI回归，不能声称六类都已验证。
- 输出Schema只是结构契约，来源语义、问法依赖、需求是否足够仍需模型评测与人工核对。
- 该Schema面向本地校验；供应商结构化输出支持范围未核实。strict输出接口可能需要适配其受限Schema，适配后仍须本地复核原契约。
- 提示正文长度、平均输出用量、延迟和重试概率尚无实测，不能保证当前粒度满足具体API预算；先测再裁剪重复规则。
- A/B尚未确认字段、版本和事件映射；本次没有修改产品代码或实现持久化、确认、重试等能力。
- 没有开展论文复现、对照效果实验、用户试用、下游执行、Skill实际运行或Windows发行验收。

优先下一步是A/B对齐此契约并用一个真实模型跑3个完整案例；修复内容错误后，再设计M2。无需等待全部后续提示一次性写完。
