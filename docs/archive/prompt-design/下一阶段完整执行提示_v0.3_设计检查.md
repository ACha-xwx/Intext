## 已核对的现状

- 当前仅有原 12 个产品模块；Skill 和导出页仍为占位，selected_skills 与 final_result 尚不足以表示完整末端流程。

- to-spec、domain-modeling、goal-prompt 有本地原文与来源记录，但不能据此宣称安装或执行成功。部分引用模板／脚本缺失，已明确原版与方法适配边界。

## 检查结果

1. 范围保持：F1–F3 暂缓，不作为开发前置，不变更 M1/M2 提示或重跑旧内容测试。
2. 交付顺序明确：先无 Skill 完整结果与保存导出，再目录／推荐／整合，最后回归与发行。
3. 新增字段和函数均标为建议接口，现有符号单独列明，没有把待实现功能称作已有。
4. 最终结果使用 not_started/draft/confirmed/stale；生成、编辑、确认、失效与纯语气切换的含义明确。
5. 内容结构单向渲染；确认需求只读，末端编辑位置明确，避免方案与提示各自改写。
6. M2 建议和 M4 新变化有单独决策和 UI 操作；未依赖的 pending 建议、可延期未知不成为永久阻断。
7. 目录原版前提与方法适配前提分开；未知条件、fallback、无匹配和明确不兼容有不同处理。
8. 取消绑定后按来源撤回贡献，独立人工编辑保留，共享变化不误删，失去依据的编辑保存于未应用列表。
9. 迟到响应检查会话实例、连接、上游、选择与末端内容 revision；补充等待 M4 期间修改决定／附注的保护。
10. 旧会话迁移不自动绑定名称或确认内容；未来版本和损坏文件不被覆盖。
11. 给出 9 个执行检查点、24 个验收场景、4 个具体任务场景和模型契约人工样例。
12. 缺密钥或外部资料时有可继续路径；6 次新模块调用上限明确，无 Skill 和语气不消耗模型调用。
