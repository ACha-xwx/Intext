# 鼠标滚轮失效：修复执行提示 v0.1

日期：2026-09-27。用途：交给另一个开发对话直接执行。当前状态：已完成源码定位和离线 Tk 事件复现，尚未修改产品、重新打包或完成物理鼠标验收。

本次只处理滚轮交互，不重做此前六项体验与 M2 的全部修复。旧开发提示和验收记录保留。

## 已核实的原因

- 当前 `src/promptsmith/ui.py:233–257` 的 `_scrollable_page()` 创建了 Canvas、内容 Frame 和纵向滚动条，绑定了布局变化，但没有接入 `<MouseWheel>`。对当前 `src`、`tests`、`scripts` 检索未发现滚轮路由实现。
- 本机 Windows、Tk 8.6.12、1120×780 下，需求页初始 `yview=(0.0, 0.789141...)`，说明内容确有溢出。对页面、标签、空任务框和空需求表分别发送四次 `delta=-120`，外层页面均不移动；直接调用 `canvas.yview_scroll(4, "units")` 则移动到 `(0.210858..., 1.0)`。
- 同一探针中的长 Text、长 Treeview 能自行滚动，外层不动。因此不能把所有控件的滚轮都无条件交给外层页面。
- 旧测试 `tests/test_experience_acceptance_fix.py:375` 直接调用 `canvas.yview_moveto(1.0)`，布局脚本也直接移动 Canvas，均未验证滚轮事件到页面的连接。这解释了旧滚动检查通过却仍出现当前问题。
- 默认尺寸下，探针里的空方案页没有溢出，不能用其不移动判断失败；修复后应在实际溢出的尺寸或内容条件下验证方案页。

证据：同目录 `acceptance_20260927_mousewheel/` 中的 `probe_mousewheel.py`、`observed_mousewheel.json` 和 `滚轮问题定位_20260927.md`。这是离线源码事件测试，不是最终 EXE 物理滚轮实测。

二、修复范围与预期交互

以下是本次修复采用的交互标准。除上述基线外，其余条目是需要验证的边界，不能写成已经复现的缺陷。

1. 外层页面滚动
   - “输入与需求”和“初始方案”都使用一致的滚轮行为。
   - 页面内容超出可视区域时，鼠标位于页面空白、标题、标签、分组框、按钮或普通单行输入框上，上下滚轮应滚动当前页面，不要求先点击滚动条或页面空白。
   - 页面顶部和底部正常停止；内容完全容纳时不产生多余空白、不抖动、不反向跳动。

2. 内外层合理接力
   - 鼠标位于长 Text、只读详情或长 Treeview 上，该控件在当前方向仍能滚动时，优先滚动内部内容，外层位置不变。
   - 内部为空、内容不足一屏，或者已经到达当前方向的边界时，将本次滚动交给所属外层页面。
   - 内部本次移动后刚好到边界，不要又用同一个事件滚动外层；下一次同方向滚轮才交给外层。
   - 同一次事件不能被自定义处理和 Tk 控件默认处理重复执行，避免一格滚轮发生双倍移动。
   - 判定应考虑鼠标所在控件及其所属页面，不能简单使用最后获得键盘焦点的控件，也不能固定操作第一页。

3. 窗口、页签和选择控件的边界
   - 切换页签后只滚动当前可见页，隐藏页不变。
   - 编辑弹窗中的文本应能正常滚动，滚动不得穿透到背景主页面；关闭弹窗后主页面仍能正常滚动。
   - 服务、协议、模型、类别等 Combobox 未展开时，普通滚轮按页面滚动处理，不得悄悄切换配置或类别；展开列表时保留列表自身的滚动和选择行为，不带动主页面。
   - 鼠标移出本应用、操作菜单或其他顶层窗口时，不得触发背景页面滚动。
   - 保留纵横滚动条拖动、文本选择、右键复制粘贴、快捷键以及已有横向滚动行为。不要把 Shift+滚轮等横向事件错误转换成纵向移动。

4. 滚动增量与生命周期
   - Windows 是本轮必做平台，兼容正负滚轮方向和不同大小的 delta。
   - 不能只做 int(delta / 120)，让连续小增量全部被截断成 0；可以累积余量，但要处理方向、目标、窗口或页签改变后的归属，不能把上一个目标的残余滚动带到另一个目标。
   - delta=0 不动作。滚动速度应适中，快速滚动可连续响应，不要一格跨过大段内容。
   - resize、内容变化、重复 refresh、新建/打开会话、切换页签、弹窗开关之后，滚轮仍有效，不重复注册、不断加速或调用已销毁的控件。
   - 保留现有 scrollregion 和内容宽度同步逻辑；本次不要求新增跨平台发行支持或触摸板手势系统。

三、实现约束

在 UI 层建立小而共用的滚轮路由，复用已有 Canvas、Text、Treeview 和滚动条，避免为每个页面复制不一致的逻辑。优先考虑有明确作用范围、可清理的事件绑定或自定义 bindtag；如使用应用级绑定，必须限制到正确的窗口和页面，并证明不会覆盖、移除其他处理器或重复注册。

特别注意：只给 Canvas 自身绑定滚轮不能自动覆盖鼠标位于其子控件上的情况；只在默认类绑定之后追加处理也可能导致 Text/Treeview 先滚、外层又滚。请检查 bindtags 顺序和事件消费结果。只有已处理或明确归属当前滚动动作的事件才应停止后续处理，不能无差别吞掉所有事件。

不要采用“进入某控件就 bind_all、离开就 unbind_all”的粗放方式抢占并清除整个应用的事件绑定。不要用缩小字体、删掉内容或隐藏下半页来掩盖问题。不要引入与此次修复无关的依赖或重构。

保持当前 M1/M2 提示、Schema、模型协议与请求、需求和方案确认、来源与冲突保护、保存结构不变；滚动不应改变正文、配置、需求版本、确认状态或会话脏状态。无需真实模型调用。

四、回归与验收

先增加能在旧版失败的滚轮事件回归，再修复。测试必须走控件事件分发及实际注册的处理器，不能直接调用新回调就算通过。可使用 event_generate("<MouseWheel>", ...)，并设置与真实鼠标目标一致的坐标/指针测试上下文；如果实现按鼠标位置路由，不能只给某控件发事件却把鼠标位置留在另一处。

用 yview 的前后变化及另一个区域保持不变作断言。直接调用 yview_moveto/yview_scroll 仅用于布置起始状态和对照，不能作为滚轮修复成功的唯一证据。

B. 空任务框和空表格上滚轮能带动外层。

E. 弹窗、Combobox 展开/收起、右键菜单及窗口切换的隔离行为正确。
F. 正负 delta、较大 delta、连续小 delta、delta=0；目标切换不串用残余量。
G. 连续刷新、切页和开关弹窗后，每次滚动只处理一次；关闭窗口无 TclError 或失效回调。
H. 现有滚动条和横向滚动仍有效，滚动不改变文本、配置和业务状态。

使用 1120×780 和当前最小窗口进行检查，并用实际溢出内容验证；需要时补充模拟 125%/150% 缩放。模拟 Tk scaling 的结果必须标为模拟，不能称为 Windows 系统 DPI 实测。运行相关 UI 回归和现有完整测试，记录实际命令、结果与失败，不引用历史 176 项通过代替本轮运行。
