# M1 v0.11：结果登记与下一步引导

日期：2026-10-01。用途：交接本次 JGS 普通使用流程修复；保留旧提示与检查记录。

## 触发问题

用户输入“讲解JGS”，补充“数值分析领域”，并接受 AI 对术语的解释。真实响应随后建议核对需求，没有新问题或方向缺口，但需求中只有 `goal`，没有 `deliverable`。程序因缺少结果字段拒绝确认，界面却只显示“当前需求缺少可识别的目标或交付物”和“核对当前需求”。用户补充“没有”“没有了”仍无法进入方案。

证据来自本机运行目录 `C:/Users/yph/AppData/Local/PromptSmith/runs/task-aea5888eef9841c885ebd55ddd476456`。这是模型的内容登记与程序引导没有对齐，不是用户必须继续补充某个隐藏要求。

## 提示调整

- 首轮加载 `M1_system_v0.11.txt`，增量加载 `M1_incremental_v0.4.txt`；原版本保留。
- 用户请求讲解某个概念，已说明结果为相关讲解内容。目标与结果分别登记，不能只有目标记录，却返回 `deliverable_identified=true`。
- 不由此添加讲义、PPT、练习题、读者、长度或难度要求；任务对象不明时仍保留含义缺口。
- 增量响应只在缺少结果字段时允许引用真实旧用户来源补记 `deliverable`；其余字段仍须引用本轮来源。程序继续验证来源存在、角色和逐字引用。
- 软件最终交付可复用提示与配套方案；`deliverable` 描述用户希望下游 AI 完成的结果，不表示本软件会直接执行该任务。
- 保持现行 `m1.v0.2` 输出结构，未新增模型输出键。例子采用通用概念，不把 JGS 写成固定业务规则。

## 程序配合

提示修订不能单独修复已经存在的旧会话。本次由程序提供可供用户确认的原任务结果：

> 想要的结果先按你的原话“讲解JGS”整理，不另加格式或篇幅要求。请核对下面的内容；需要调整时在上方说明。

显示这个说明不会修改需求。用户点击“确认需求并生成方案”后，才以原任务全文登记结果，增加用户确认来源，并进入既有方案生成流程。

建议仅在目标已明确、分析有效、没有真实结果缺口、未决方向、冲突、未处理解释或待分析回答，且没有用户撤回或延期的结果记录时出现。普通确认接口不会自动补记；带显式选项的确认仍检查预览是否变化，并原子提交。

结果确实不明时，界面直接问“你希望另一个 AI 最后给出什么结果？在这里简单说明就好”，主按钮引导回回答区。没有当前问题时隐藏“先跳过”和“我不确定”，避免把无问题状态显示成仍需回答。

准备进入方案时，回答区说明：

> 请核对下方需求；没有要补充或修改的地方，点击底部“确认需求并生成方案”。需要调整也可以在这里说明。

## 输入输出举例

已有任务 `讲解JGS`，有效需求只有目标与术语含义，分析最新，无缺口或冲突：

```json
{
  "missing_direction_fields": ["deliverable"],
  "suggested_task_result": "讲解JGS"
}
```

以上是程序预览的新增字段，不是模型输出接口。用户点击显示的确认按钮后，程序新增 `field=deliverable`、`kind=user_decision`、`text=讲解JGS`，以本次确认记录为来源；不增加格式和篇幅要求。

若 JGS 含义仍未确定，或用户仍在决定想要的结果：`suggested_task_result=null`。保留具体问题或既有草稿入口，不把尚未接受的 AI 理解直接当成用户要求。
