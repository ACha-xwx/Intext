# M1 v0.21 / 增量 v0.14 修改说明

## 这次解决什么

模型之前虽然已经有 `model_judgment` 字段，但修正提示只说“尽量填写”，模型输出不完整时，程序只能依靠旧字段或恢复逻辑判断。现在明确规定：只要是正常的 `status=ok`，模型必须同时告诉程序本轮回答是否充分、还缺哪些关键缺口、是否继续访谈以及判断把握。

## 模型和程序怎样配合

- **模型判断**：理解用户自然语言，区分完整、部分补充、含义不清和没有回答；识别简称、术语和上下文线索；决定继续追问、给出待确认理解，还是进入需求复核。
- **程序校验**：检查 JSON、Schema、来源引用、缺口编号、版本和状态迁移；发现模型判断与下一步动作矛盾时，发回修正提示。
- **安全边界**：旧的追问轮数只不再作为内容质量门槛；程序仍保留内部修正次数，防止模型接口异常造成无限调用。这个内部上限不会要求用户补写术语全称，也不会把语义不足直接当成技术错误。

## 语义错误和技术错误的区别

术语不明、信息不足、用户说“你自己查”属于正常访谈，模型应返回 `status=ok`，保留缺口并继续提问。若历史模型仍返回语义型 `input_error`，程序会按语义标记或相关说明转成可继续的访谈。

普通 `invalid_input`、JSON/Schema 无法解析、网络/API/协议失败仍按真实错误记录并保留会话状态，避免把真正的技术问题静默吞掉。

## 验证边界

本次已通过 M1 模型判断、语义桥接、恢复、增量及技术错误回归和编译检查。尚未用真实模型重新跑 JGS；因此“模型能否在实际 API 中稳定提出合适候选”仍需真实调用验证。
