- 模型参与 M3 时，只能从本次候选 ID 与快照中排序／解释；返回对应 key_work_id／step_id、匹配理由、输入输出如何对应、兼容性与缺失前提、局限及无匹配说明。名称、来源链接、许可与能力基础由程序从目录回填，不能让模型自创。
- 校验未知 Skill ID、候选外 ID、无效步骤、过期版本、重复绑定、不可能环境及结构化错误。非法响应不替换原有有效数据。
- 程序规则直接得到的列表明确标“目录筛选”；不能伪造“AI 已推荐”或伪造模型用量。需要 M3 时最多一次请求完成本批解释；没有候选直接返回真实无匹配。
- UI 逐项展示用于哪项工作、理由、所需条件、来源和核验程度，明确不是已安装／可直接执行的保证。模型推荐不等于用户选择。
- 对明确不兼容的条目不作为可执行推荐；未知前提可作为条件候选，标明差什么。支持单选／多选／取消、全部跳过和无匹配继续。

### C3. 用户选择和 M4 整合

- 只有用户明确选定的 ID 和本次快照可进入整合。保存 skill_id＋记录版本／hash＋对应 key_work_id，而非只存一串名称。
- 保留初始方案原件；M4 输出新的最终草稿与可追溯改动记录。用确定性结构覆盖能保证的部分，确需内容整理时复用公共模型调用。
- 每个被采用的 Skill 必须落到具体工作步骤、输入、输出、执行前提、检查标准及失败／不可用时的处理方式。不能只附“建议使用 A/B/C”。
- 若原 Skill 依赖特定宿主，不能声称它在任意 AI 窗口都能运行。方法摘要可独立使用时，标成来源于该 Skill 的方法适配；实际工具调用有前提时，写明前提和不满足时的替代步骤。
- Skill 选择不是对额外费用、权限、数据外发或范围扩张的一揽子同意。新增变化单列原因、影响和待确认项；用户可以拒绝或跳过。改变已确认硬约束的方案不能直接生效，应返回需求修改／重确认路径。
- 对未解决但非阻断的前提，可形成条件性草稿；正式可用结果不能把未获确认的能力、权限或成本当成既定事实。存在可行无 Skill 替代时保留替代分支。
- 用户取消全部 Skill 后，从当前已确认初始方案重建无 Skill 结果，不只删名称而留下引入的额外步骤、依赖或费用。
- 不因选择一个示例／Skill 推导用户接受其全部特征。最终复核展示采用了哪些变化、哪些没有采用、哪些还需决定。

### C4. 模块提示与契约交付

新 M3／M4 如果采用模型调用，分别交付静态系统提示、输入／输出 Schema、字段映射、正常和边界人工样例。提示说明包括用途、调用时机、输入字段、正文、输出、未知／失败处理；人工样例标记 fixture。模块可合理合并以减少调用，但仍隔离“推荐”与“用户已选择后整合”的信任边界。

公共输入最低应可追溯 request_id、task_id、来源需求版本、plan_id/version、目录／选择快照版本，以及本次真实记录。正常结果与结构化错误互斥。程序持有 request 上下文，不能照信模型回传的版本或确认标记。

M4 无 Skill 模板必须交付模板及渲染版本、输入契约和输出检查，不需要虚构一份已经实测的模型系统提示来凑模块。

## 7. 版本、失效与失败恢复必须真实接线

下面的语义不可省略，字段名称可适配现有实现：

| 事件 | 程序应有的行为 |
|---|---|
| 修改任务、类别、正式需求或其他现有需求变更入口 | 沿用需求失效规则，并使推荐、选用适用性与最终结果过期；旧内容仍可追溯 |
| 编辑／重生成初始方案，删改步骤或关键工作 | 方案待重新确认／复核；依赖旧方案的推荐和结果不能继续视为有效 |
| 新一轮推荐、目录版本或记录内容改变 | 旧候选适用性待复核；不得用同名新条目静默替换已经选择的内容 |
| 选择、取消 Skill 或修改兼容前提 | 选择 revision 更新，旧整合请求失效，最终结果待重建 |
| 只切换语气 | 内容依据不变，只重新渲染规定包装 |
| 编辑最终结果内容 | 最终 revision 更新，旧确认撤销，要求重新复核 |
| 模型返回时任一依赖版本、目录 hash、选择 revision 或会话身份已变 | 拒收迟到结果，记录原因，保留当前数据 |
| 同状态重复点击／处理中再次点击 | 不重复扣额度或同时发相同请求，按钮和状态有反馈 |
| JSON／Schema／业务校验失败、超时、鉴权或网络失败 | 失败与用量如实记录；不清空已确认方案，不偷偷接受部分响应 |
| 取消等待、切换服务、切换会话、关闭／重开程序 | 请求取消或失效可追溯，旧回调不能写进新上下文 |

特别测试 A→B→A 的选择变化：内容回到原值也不代表旧请求重新有效，不能只比较字符串集合，应使用请求期的唯一快照／revision。

结果依赖建议至少绑定 task_id、requirement_version、plan_id/version、catalog_version/hash、selection_revision 和内容／渲染版本；不适用的依赖为空但含义明确。具体实现与字段映射落入交接。

保存和导出不能把“曾经确认过”当成“当前版本已确认”。有效性校验从生产入口运行，不能只靠 UI 按钮禁用。

## 8. 界面操作与错误文案

沿用现有导航，至少让用户能清楚完成：

确认初始方案 → 选择“查找 Skill”或“跳过 Skill” → 查看推荐及条件并选择／取消 → 生成最终草稿 → 复核／编辑／确认 → 选择语气 → 复制提示／导出 Markdown／保存 JSON。

- 每个页面说明当前状态、下一步和按钮不可用的具体原因，例如“初始方案已修改，请先重新确认”。不要只显示“未就绪”。
- 无匹配、未选择、主动跳过、目录损坏、模型解释失败是不同状态。目录坏了应报真实错误，同时允许无 Skill 分支；不能把坏目录伪装成搜索无匹配。
- 初始方案确认后不能自动发 M3/M4 付费请求或替用户勾选 Skill。
- 长文本可选中、复制、右键和滚动；沿用既有滚轮接力与控件字号。所有新增交互都通过状态／workflow，不另造只存在于控件中的确认标记。
- 调用有等待反馈和避免重复点击机制；用户关闭／取消后旧响应不得回填。导出成功显示实际文件位置，失败保留编辑内容。
- 本轮只落实功能可操作与文字可读，不做新的外观设计。

## 9. 验收：测试生产路径，不以数量代替结论

新功能的关键状态与输出风险先写能暴露错误的测试，再实现。以下测试要经过生产输入组装、解析、状态应用或渲染／保存入口；仅构造漂亮 JSON 不算接通。

| 编号 | 场景与预期证据 |
|---|---|
| T01 | 编程、写作各一条从已确认需求／方案到无 Skill 结果，复制与 Markdown 含完整内容；不产生额外模板模型调用 |
| T02 | 需求／方案未确认、来源过期、关键工作未复核时，生产最终生成／确认入口拒绝越过前提；已保存草稿可继续查看 |
| T03 | 中性与适度礼貌在多种任务文本下去包装后逐字一致，切换不改选择、未知和状态 |
| T04 | 目录有真实适用项、无匹配、目录损坏三种结果明确区别；均有无 Skill 路径 |
| T05 | 模型编造候选外 ID／链接、引用已删除步骤、重复绑定、宿主冲突或返回错误时，校验拒收且原状态不变 |
| T06 | 选用一个 Skill 后，最终步骤实际体现其输入输出与条件；无关能力不混入；未确认范围／费用／权限不生效 |
| T07 | 取消部分／全部 Skill 后重建，新增步骤及依赖按绑定正确撤除，无 Skill 结果与当前基线一致 |
| T08 | 需求变化、方案编辑／重生成、关键工作删除、目录 hash 变化、选择 A→B→A，各自使相关迟到响应失效 |

## 10. 仅验证新模块的有界真实调用

本轮暂不复测旧 M1/M2 内容问题。发送本文件作为任务时，新模块真实调用预算默认 **最多 6 次**，包括连接检查、模型目录、失败尝试和任何修复重试，不自动用满。用户指定更低预算时以其为准。

使用已经明确授权且可安全取得的官方 DeepSeek 配置：`deepseek-flash`、OpenAI Chat Completions。公共产品接口仍须支持其他已接入协议；这里仅限定本轮有凭据的真实服务。不因为方便换到未经授权的服务，也不因为还有次数就增加调用。

只能使用开发窗口已有的明确授权运行时配置，或用户指定的安全输入方式。不要从聊天转储、浏览器、其他进程或未知凭据文件搜索密钥；不要假设能继承另一个已结束进程的内存。密钥不进入命令行字面量、代码、报告、保存、导出或发行包。

拿不到密钥时，继续完成离线实现、测试、构建和可复验脚本，将真实测试标“未执行”，不要让整体工作停住等待。鉴权、余额不足等错误停止网络重试并继续独立工作。

建议测试分配：

1. 先构造一个编程、一个非编程的已审核人工方案夹具，并通过生产流程完成测试确认。两例的来源、未知、运行前提和完成标准清楚，不能把带已知错误的旧 draft 偷偷改成已确认。
2. 对实际适用的真实目录候选做 M3 最多 2 次；对测试操作者明确选定的记录做 M4 最多 2 次（若 M4 使用模型）。无候选直接无匹配，无需调用模型凑次数；无 Skill 模板也不需要真实调用。
3. 最多留 2 次用于新模块有具体原因的修订或失败恢复。重试计入总预算，不重跑旧 M1/M2 案例占用预算。
4. 新模块全部采用确定性实现时，按实际情况不调用模型，准确报告“规则／模板验证”。不要伪造 AI 推荐或用量。

必须明确测试链组成：本轮可为“人工已确认方案输入＋真实 M3／M4 输出”，不能描述为整个新链条从 M1 起都经过真实模型端到端验证。M1/M2 的真实历史证据仍是原 7 次，内容问题仍未修复。

脚本计数并拒绝超限。保存真实请求参数、实际候选／选择快照、原始输出、返回模型、usage、耗时及失败；缺失用量保留 null，不把估算写成真实值。模型没有实际执行 Skill，仅生成匹配／整合内容，报告也应如此表述。

新模块内容检查：候选 ID 和来源真实；能力不超目录；整合落到工作、输入输出与前提；原约束和未知不丢失；新增范围／成本／权限仍需确认；取消 Skill 后额外内容撤除；同一语义正文的语气包装保持一致。内容失败与程序失败分别记录，原始响应保留，不自动确认来赶进度。

## 11. 打包与清晨交接

保持现有单文件构建方式。修改 spec 和资源定位时只打包运行所需的新提示、Schema、模板和目录，不把整个 output、研究材料、历史 API 记录或密钥加入包。

构建前保留当前可运行发行物的可识别备份和 hash；构建失败不删除唯一可用版本。新 EXE 启动、资源加载与末端可离线操作需要实际证据；项目外测试用新的独立目录。另一台电脑、真实 DPI 或真实鼠标不足时列待验证，不伪装已经完成，也不自动成为本轮所有代码工作的阻塞。

本轮证据写入新的 `output/prompt/_design/acceptance_<实际日期>_final_skill/`；已有同名目录就加 run 序号，不覆盖。至少交付：

- 实际实现范围和变更文件清单；未实现／待核验项及其原因。
- 新提示与模板／Schema 版本、输入输出映射和正常／边界样例；注明模型实测还是 fixture。
- 目录来源、核验状态、版本、快照 hash、宿主条件及必要署名说明。
- 功能测试、真实小样本、UI 接线、源码／EXE 结果分别报告；保留所有失败原始证据。
- 一份有明确起点和预期结果的手动操作说明：无 Skill、选 Skill、取消、改需求失效、保存重开、导出。
- 最终 EXE 路径、hash、构建／启动命令、打包资源核对。
- 更新 `docs/开发交接.md`、`output/prompt/_design/README.md` 和 `CHANGELOG.md` 的真实状态。
- 在 `docs/明早待确认.md` 追加本轮仍需用户处理的最少事项，已有内容保留；若没有则写无，不把普通代码选择留给用户。

如果存在外部阻塞，交付已经通过的可运行检查点并准确说明剩余范围；不要把仅 B 完成标成整个 C 也完成，也不要因为 C 某个条目无法核验就抹掉已完成的 B。

最后给用户的回复只需说明：已接通哪些路径；实际测试与内容质量分别如何；哪些仍需处理；打开哪个 EXE、查看哪个报告。开始执行后不要以“方案已写好，要不要开始”收尾。
