## S1：让现有完整链路有明确下一步

方案确认后，主操作应带用户到下一件尚未完成的工作，而不是停在已确认方案：

- 尚未作 Skill 决定：进入 Skill 页，明确提供“查找已核验目录”和“跳过并生成最终草稿”。无匹配或目录不可用时，不阻断无 Skill 路径。
- 已选 Skill，尚未完成适配/整合：进入对应可操作状态；整合仍需当前方案和选择有效。
- 最终草稿待复核：进入最终页；有 M4 待处理变化则定位具体复核项。
- 最终结果已确认：进入最终页，可复制、导出或主动发起短文本试运行；不要自动调用模型。
- 上游需求/方案失效：优先引导修复源头，而不是继续使用旧 Skill 绑定或旧最终提示。

同步更新方案页、需求页的下一步文案，保持主按钮动作、页签状态与实际可做的事一致。不能因反复点击主按钮而自动重复请求模型。导航改变只需聚焦现有控件，不进行整页视觉重设计。补至少一条从方案确认后到无 Skill 最终页的 UI 回归，以及有 Skill/待复核/失效三个分支的聚焦检查。

## S2：M5 局部示例与反馈，最小可用版本

把 M5 放在需求引导阶段，用户可主动使用；仅当某项评价标准难以表达时，界面可轻量提示。一次锁定一个 `criterion_id` 或一条待澄清描述，生成 A/B 两份短文本，二者只在目标维度有可比较差别，其余共同前提保持相同。显示这是“帮助表达偏好”的示例，不是完整任务成品。没有足够上下文生成可比示例时明确说明原因，允许回到普通追问。

建议（非现成接口）为生成调用提供：当前任务/类别、相关已确认字段及来源、目标维度、现有未知、硬约束、示例长度上限、当前需求版本。输出使用严格 JSON，至少含 `dimension`、`shared_assumptions`、`option_a`、`option_b`、`difference_summary`、`unsupported_assumptions`；程序校验两项不为空、长度有限、目标维度一致、无明显硬约束冲突。例子可以暂用可见占位或虚构演示数据，但不能暗中写回需求卡。结构字段名应与实际代码协调，并在交接中标明最后接口。

用户可选 A、B、都不喜欢、跳过，并写一句反馈。选择 A/B **不等于接受它全部特征**。反馈归纳只抽取用户指出的具体偏好，成为待确认候选，显示“来自本次示例反馈”的来源；用户能编辑、接受或拒绝。接受后走现有需求卡版本/确认/下游失效规则，不能开第二套确认状态。无具体反馈、只点 A/B 时可以提出窄范围的待确认表述，但不能声称已确认；“都不喜欢”和“跳过”不生成正向标准。已有明确标准不重复追问。

M5 请求与反馈归纳分别记录发起时需求版本、会话身份和请求标识；切换会话、编辑相关需求或取消后到达的旧响应不得污染新会话。模型失败、坏 JSON、超时、用户中途跳过时保留原需求；界面给出重试/返回普通追问的操作，不把失败算作需求完成。会话重开后示例、反馈和候选的状态应可辨别；至少保存必要的内容与来源，避免写入密钥或完整不必要的请求包。

准备两个小检查：正常情形为“摄影社招新通知的语气还拿不准”，A/B 只在“活泼程度”上有差异，用户反馈“喜欢 B 的直接，但不要口号”，最终只出现一个待确认的语气标准；边界情形为用户选 A 但不评论，A 中虚构的日期/地点/联系人不得进入已确认要求。另测“都不喜欢”、跳过、迟到响应和保存重开。可用人工 fixture 测状态，但至少在真实任务中看一次模型生成的例子及反馈归纳是否忠实。

## S3：短文本试运行与真实用量

在最终结果已确认、来源仍有效时，提供清楚的“试运行”操作。使用**当前复制/导出的同一份最终任务提示正文和语气**，发给用户当前选择的模型与协议；不允许为了试运行暗改提示内容。用户可设置很小的文本输出上限或沿用经确认的默认值，明确这是短试运行而非完整执行。未配置连接、提示已过期、用户尚未确认最终结果时禁用并指向可修复位置。试运行必须由用户点击触发，不随确认、语气切换、打开会话或导出自动启动。

复用现有 API 配置和错误分类；如当前客户端只有 `complete_json`，按现有三个协议的模式补一个受控纯文本调用能力，保持服务商/协议/模型分离，不用 JSON 对象模式去强迫下游任务输出。应有超时、响应大小/输出上限和取消/重复点击保护。无论成功失败，记录发生时间、协议与模型、final revision、提示正文摘要/hash、实际使用的语气、延迟、接口原样返回的 usage 或“服务未提供”、错误类别。展示短文本输出，供用户复制；试运行输出**不能**写回已确认需求、初始方案或最终方案，也不能冒充正式交付物。

准备阶段用量与下游试运行用量分别呈现；只有已有调用确实有可核验 usage 时才汇总。无 usage 不填 0，不能从字符串长度猜 token，更不能宣称总费用。建议（非现成接口）在会话中维护 `trial_runs[]`，每条指向生成它的 `final_revision` / hash；上游后来修改时保留历史结果并标“基于旧版提示”，不悄悄重用。保存重开后至少看得到最近试运行文本、版本与用量状态。

正常检查：已确认无 Skill 摄影社通知提示，点击一次得到短文本和真实 usage（若服务返回），准备与试运行分开展示。边界检查：提示在点击/响应之间失效，迟到结果不能覆盖当前页或变成当前版本的结果；API 超时或无 usage 时有明确状态，用户可继续导出原最终提示。离线测试覆盖三协议纯文本请求/解析，不把本地 HTTP stub 写成三家真实服务均已测。
