# M1 system v0.22

这版把模型和程序的分工说清楚：模型判断用户回答是否足够、还缺什么以及下一步怎么问；程序只保存状态、检查结构和维护版本。

本版特别处理简称和含糊回答。模型可以根据领域、用途和上下文提出待确认理解，用户不需要先写出正式全称；连续不明确时应换成区分候选的具体问题，不能重复把用户卡在“请写名称”。旧的轮数和问题数量字段不再作为内容质量门槛。

这是提示设计与离线契约检查版本。尚未把本补充单独做真实模型 A/B 对比，真实内容质量仍需在固定任务上复测。

## 本轮补充（2026-10-06）

- **改了什么：** 写清快速、标准、深入三档分别要问到什么程度。三档的区别是要覆盖的信息范围不同，不是简单规定问几轮。
- **为什么改：** 之前三档容易问出差不多的问题，深入模式也可能过早结束。现在模型要根据当前档位还缺哪些重要信息来决定是否继续。
- **用户会看到什么：** 信息不足时继续看到一个可以回答的问题；模型判断和下一步按钮互相矛盾时，程序会保留当前信息并回到追问，不把这种内容问题显示成技术报错。
- **仍然保留的边界：** JSON 损坏、字段结构不对、来源编号错误、网络/API 失败等真正的技术问题仍会提示错误；本轮未用真实模型重新验证三档内容差异。
