## 案例01：正常路径

输入：[01_报名网站.input.json](<../../../resources/prompts/examples/01_报名网站.input.json>)。人工参考：[01_报名网站.expected.json](<../../../resources/prompts/examples/01_报名网站.expected.json>)。原话：“帮我做一个活动报名网站，不做付款。”现有卡为空，允许追问，两轮预算、每轮最多两题。

**固定判据（也供后续真实输出判读，允许措辞和候选粒度不同）：**

1. 保留网站目标、网站交付物与明确“不做付款”限制，来源可定位到u1；不要求恰好生成三条相同文字。
2. 用途未说明时优先问实际使用或演示，不先要求选择云服务、数据库、预算；不重问是否付款。
3. 未知放入gaps；不能把选项或自拟做法写成用户硬约束。建议coding但不代替用户作持久分类选择。
4. questions不超过预算，各题前提已知且独立；当前应走ask，不能声称已经确认、保存或直接生成方案／Skill推荐。

**本轮实际观察：** 人工expected含目标、不付款硬约束和交付物三条候选，引用均为用户原文；仅问一个用途问题，g1保留方向缺口，next_action=ask。逐项设计判读通过。原文“课堂演示”可以后续改为更宽的“仅做演示”；“已记下”可由C换为“这次的范围不包含付款”，减少持久保存的暗示。本轮保留原fixture，不追改基线。

**自动检查：** 输入及人工expected均通过各自Schema；所检查的ID、引用、逐字quote、字段、问题—缺口关联、预算和状态规则通过。**真实模型测试：待实测；raw不存在。**

## 案例02：明确修改与预算耗尽同时发生

输入：[02_冲突且预算耗尽.input.json](<../../../resources/prompts/examples/02_冲突且预算耗尽.input.json>)。人工参考：[02_冲突且预算耗尽.expected.json](<../../../resources/prompts/examples/02_冲突且预算耗尽.expected.json>)。旧版4已确认“不做付款”，本轮说“还是加上在线付款吧”；remaining_rounds=0且allow_questions=false。

**固定判据：**

1. 理解为用户明确变更，提出针对r2的replace候选；引用u2，不直接覆盖旧确认、不伪造已接受事件。其他既有目标和课堂演示用途仍在程序快照中，无需在增量输出里重复一遍。
2. conflicts保留r2与新proposal的关联，change_intent=explicit_change；新旧差异可核对，readiness不能当作确认。
3. questions必须为空，预算耗尽不能促使模型猜付费方式、价格或支付渠道。
4. next_action=resolve_conflict，保留阻断项，提示在需求卡接受或编辑变更；不得因没法再问而输出review_requirements、宣布完成或进入方案／Skill阶段。

**本轮实际观察：** 人工expected只有一条针对r2的replace候选，c1同时引用旧项与新建议；有blocking缺口，questions=[]、next_action=resolve_conflict，无确认字段。设计判读通过。旧例g1使用origin=ambiguous承载待处理冲突，但change_intent已明确，不能据此理解成“用户没说明要不要改”。是否细分待接受状态由A/B后续决定，不在今晚改枚举。

原衔接文字“其他尚未明确的付款细节会继续保留”不够精确，gaps并没有逐项列出这些付款细节；后续文案建议改“付款细节尚未确定”。这属于措辞问题，不能用来声称卡片已记录了所有未知。

**自动检查：** 输入及人工expected均通过各自Schema；引用、replace目标、冲突关联、阻断项、零预算及冲突优先通过。**真实模型测试：待实测；raw不存在。** 本例零预算本来就禁止任何提问，不能单独证明F01在有预算时生效。

在项目根目录重跑，默认只输出新的检查结果，不覆盖旧日志：

```powershell
pwsh -NoProfile -File './output/prompt/_design/_checks/check_m1.ps1'
```

需要保存时加`-ReportPath`指定未使用的新文件名；脚本拒绝覆盖已有记录。真实调用发生并按README保存后，可指定实际输入和原始返回进行同类检查，例如：

```powershell
pwsh -NoProfile -File './output/prompt/_design/_checks/check_m1.ps1' `
  -InputFile './output/prompt/_design/_runs/<实际运行目录>/input.json' `
  -ResponseFile './output/prompt/_design/_runs/<实际运行目录>/response.raw.txt'
```

上面的运行目录是占位符，今晚并不存在。外部响应在检查器中标为来源未核验，必须结合调用记录确认是真实模型输出；它不会因为文件名叫raw就自动改判为实测。供应商外层响应如有包装，raw保存模型正文原文，另保留必要响应元数据，不能把人工expected替进去。
