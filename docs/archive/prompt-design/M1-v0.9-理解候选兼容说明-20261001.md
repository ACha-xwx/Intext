# M1 v0.9：上下文理解候选

本次为流程简化执行提示 v0.3 的程序接入改动。首轮资源为 `M1_system_v0.9.txt`，增量资源为 `M1_incremental_v0.2.txt`；输入和输出资源为 `M1_input_v0.3.schema.json` 与 `M1_output_v0.3.schema.json`。旧提示、旧 Schema 和真实输出均保留。

## 最小扩展

继续使用 `pending_interpretation` 候选。只有需要在当前区域由用户判断的解释，才带可选字段：

```json
"interpretation_for": {
  "gap_id": "对应的方向性缺口",
  "question_id": "对应的问题编号，未形成问题时为 null",
  "reason": "已有用户信息为什么支持这一推测"
}
```

程序校验关联的真实缺口、问题、字段和范围；解释只能是 `new`、`pending_interpretation`、`unspecified`，必须有逐字用户上下文来源。一轮至多两个解释，针对同一个方向性缺口；与旧未处理解释合计不超过两个。同一内容不能换编号重复生成；用户已拒绝或跳过解释后，没有有效的明确重开依据不得再自动猜。

输入增加可选的 `state.pending_proposals`、`state.pending_questions`、`state.interpretation_history`，供模型看见未处理草稿和用户的既有选择。程序只发送语义字段，不发送运行时请求、版本元数据或密钥。历史草稿的输入摘要至少保留编号，缺少字段就如实省略；模型输出仍必须满足完整候选结构，程序不会补造缺失内容。自由补充的回答可以有 `gap_id=null`；这种回答可用于提取需求，但不能凭空产生关闭某个未知的 `gap_updates`。

## 确认和兼容边界

接口外层 `schema_version` 仍为 `m1.v0.2`，这是不改变旧必需字段含义的可选扩展。新解析器继续接受没有扩展字段的 v0.2 输出；旧会话缺少新增集合时使用空集合。v0.1 的显式 legacy 资源加载仍保留。**旧解析器不能处理带新字段的响应**，因此提示、Schema、程序和发行资源须同步更新；不能只替换提示文件。

解释输出本身不会解决未知或确认要求。Session 根据用户明确的单项选择记录来源，只处理对应解释和缺口；其他候选保持原状。UI 展示推测来源，并提供补充或草稿出口。接受一个讲解对象不等于验证模型给出的领域知识。

增量模式继续保留模型省略的旧未知与未解决冲突，并保护冲突参与方。输入冲突可增加 `proposal_ids`，使未处理的候选参与方在后续分析中同样受保护；允许引用旧草稿不代表用户已接受。原截断识别、超时与主动有限重试规则没有改变。

## 验证边界

新增 `tests/test_m1_interpretation_guidance.py` 检查有依据解释、两选项上限、错误关联、冒充用户决定、无来源、重复猜测、旧格式兼容与输入草稿保留。用例中的领域解释只是合成验证数据，不是产品固定答案。该资源本轮仅有离线程序验证；真实模型解释的合理性仍需真实内容检查。最终全量测试、界面和 EXE 结果以本轮总交接为准。
