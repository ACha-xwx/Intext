## 已实现行为

- 创建、保存、重开版本化会话；旧文件缺省字段可迁移。
- 记录来源、需求候选、正式需求、冲突、缺口、问题历史、追问预算和 API 调用摘要。
- 用户可以接受或忽略候选、手工编辑或撤销需求、回答／跳过／标记不确定，并确认特定需求版本。
- 模型输出只进入候选区，不能自动确认需求、覆盖用户决定或启动下游步骤。
- 需求变化使对应确认和下游结果失效；迟到的模型响应按请求版本拒收。
- 成功分析绑定当前需求版本；修改任务、类别、需求或回答后旧分析依据失效。确认前检查当前版本、方向性要求、冲突、阻断未知、待复核项和依赖。
- 候选批量接受先完整校验、再一次提交；失效目标、重复目标或悬空依赖不会造成部分写入，重复点击不会重复添加。
- 未知项不会因模型省略、相同字段／范围的其他候选或新缺口 ID 而自动消失。自由回答先保存原话和 gap 对应；模型通过 `gap_updates` 建议完整、部分、仍未知或不再适用，程序校验回答、来源、目标和版本后才更新，并保留审计历史。
- 跳过／不确定问题默认不重复询问；用户最新消息明确要求重新讨论对应范围时，模型可通过 `question_reopens` 建议重开。程序检查原历史、最新逐字依据、范围关联和预算，无关消息或模型 reason 不能放行。
- 程序产生的待复核状态不会被模型空列表清除；模型只能新增复核建议，用户明确复核或对应活动项被替换／撤回后才解除阻断。
- 编辑、替换和撤销会统一维护正式需求、缺口、待回答问题、候选、冲突和待复核列表中的活动引用；冲突只在整次状态更新结束后协调，避免候选失效时提前消失。构建 M1 输入和确认前都会拒绝悬空引用。
- 已登记且尚未解决的冲突会保护其中仍有效的正式需求参与方。模型即使保留原冲突编号，也不能通过遗漏或换掉旧参与方使冲突被协调删除；语义解析和状态应用入口都会在业务状态写入前拒绝此类响应。用户真实撤回冲突一方后，现有引用改写流程仍可正常关闭冲突。
- 重复追问至少按字段和适用范围判断；不同交付物可继续询问同类字段，同范围无新证据的跳过／不确定问题仍会被拦截。
- `input_error`、网络、鉴权、超时、响应格式和 M1 校验失败均按失败记录；已有业务状态和追问预算保持不变，用量不可得时保留 `null`。
- 界面允许在普通候选仍为草稿时先回答问题；新分析不会覆盖未处理草稿。选中项详情显示来源、类型、强度、范围、依赖及修改差异，并提供显式“标记已复核”操作。
- 模型请求在后台线程执行，Tk 主线程通过队列更新界面。
- API Key 只保存在当前进程内存，不写入会话、运行证据或发行资源；配置对象的调试表示也隐藏密钥。
- 每次真实调用可保存实际输入、提示、Schema、原始响应、参数、用量、耗时和检查结果。
- M2 只消费 `confirmed_requirements_version == requirement_version` 的需求快照；候选、冲突、待复核需求、方向性未知或引用异常会在调用前阻断。
- M2 正常输出必须精确覆盖全部正式需求，保留全部可延后未知，并通过 ID、交叉引用和无循环依赖检查；结构化错误、非法输出或过期响应不覆盖已有方案。
- 合法结果只成为方案草稿。方案 ID、版本、确认、失效、来源快照、归档和关键工作复核由程序维护；用户确认当前方案版本后才记录 `confirmed_plan_version`。
- 用户可编辑目标和步骤，新增、删除和重排步骤，并复核关键工作。普通方案编辑不改变需求版本；实际需求变化使旧方案保留为 `stale`，重新生成时旧方案进入 `plan_archive`。
- 正文、按钮、表格和编辑框采用 11 pt 字体；主页面在高缩放下可纵向滚动，表格提供横纵滚动条。需求、方案步骤和关键工作使用多行编辑窗口；主页面、弹窗和只读详情支持相应右键菜单及快捷键，表格可复制完整选中记录。
- 草稿、修改、复核、确认、来源快照、未决项和归档均随 JSON 保存重开；旧 M1 会话补齐方案默认值，未知未来会话格式明确拒绝。
