## 原因与修改

1. 原 M2 请求日志位于用户数据目录 `task-2f1fbb2dd3194931b6d7f88bc152afc9/20261001T031543.880441Z_m2-5e04eb5f15ca434bb681e4524b975498`。实际发送 `max_tokens=8192`，约 37 秒后返回截断；不是 120 秒等待超时。旧处理丢失部分响应与用量，不能确定该次思考和正文分别消耗多少。
2. 对精确的官方 HTTPS 地址及两款已核实模型 `deepseek-flash`、`deepseek-v4-pro`，JSON 生成使用 65536。三协议适配器分别设置对应额度字段和低思考强度字段。未知服务仍保留兼容参数，避免发送超过其能力的额度或专属参数；连接测试和短文本试运行的独立限制未扩大。
3. M2 加载 v0.2，保留 v0.1。明确只写初始方案，不展开下游正文；逐条覆盖需求、保留全部未知与术语不确定性，压缩重复说明。区分软件交付物与下游任务成果：方案中的交付物指下游 AI 应完成的成果，不能把用户要的讲义改成“只写讲义计划”。
4. M2 截断后在同一主操作位置显示“重新生成方案”。仅用户点击时重新生成完整 JSON，减少重复说明，不拼接残缺内容、不自动循环调用；保存重开仍可恢复该入口。需求和已有结果保留。
5. M1-M5 补齐停止原因、部分响应、模型响应 ID 和用量记录。失败响应只供诊断，不能进入已完成或已确认结果。
