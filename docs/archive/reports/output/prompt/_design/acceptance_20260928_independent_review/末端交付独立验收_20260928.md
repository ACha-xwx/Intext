# 末端交付与 Skill 增强独立验收

日期：2026-09-28。依据：`下一阶段_最终交付与Skill增强_完整执行提示_v0.3.md`，对照当前源码、测试和 run03 交接证据。本轮只读验收产品，未修改产品代码，未调用真实模型。

## 结论

主流程已经接入，且本机全量 309 项测试、编译检查和现有 EXE 启动烟测通过。但发现会使用户决定与正式交付不一致的缺陷。本轮不能按“完整验收通过”进入下一功能阶段；先修以下高优先项，再做针对性复验。M1/M2 真实模型内容问题 F1-F3 依用户决定暂缓，不列作本轮阻断项。

## 发现

1. **P1：拒绝 M4 变化后，依赖该变化的方法动作仍可确认。** `src/promptsmith/finalization.py:604` 仅把变化标为 rejected 并清除复核 ID；`render_canonical_body()` 仍输出原 `method_actions`（约第 716-724 行），`validate_current_final()` 未核对贡献对已拒变化的依赖。构造贡献引用 `change-1` 后拒绝该变化，`confirm_final()` 仍可成功，正文仍包含相关动作。应停用依赖动作并应用合法 fallback；没有可用 fallback 时要求取消绑定。覆盖接受、拒绝、取消与保存重开。

2. **P1：正式 Markdown 导出未验证当前来源。** `src/promptsmith/exporter.py:16-22` 只看 confirmed 状态和 revision，没有调用 `validate_current_final(..., require_confirmed=True)`。在已确认后使方案版本变化、但最终状态尚未更新的复现中，导出仍标“最终版本”。文件选择对话框打开期间也存在状态变化窗口。正式导出必须在实际写入前重验基线、绑定、正文与确认状态。

3. **P1：重复 M4 整合会带入上一轮变化，形成无法处理的同名变化。** `src/promptsmith/finalization.py:333-403` 重建草稿时保留旧 M4 的 accepted additions、pending changes 和 change decisions；`src/promptsmith/delivery_workflow.py:377-415` 再追加本轮变化。若模型复用 `change_id`，`decide_m4_change()` 因匹配数不为 1 拒绝操作；旧轮次的采纳项也可能未经本轮决定继续保留。应按 generation request ID 隔离本轮变化和决策，并明确旧贡献的保留／撤销规则。

4. **P2：正常 v0.2 会话把当前 Skill 镜像误判为旧格式遗留。** `src/promptsmith/session.py:120-133,212-214` 对所有加载版本都把 `selected_skills` 加入 `legacy_selection_unresolved`。该字段在 v0.2 又是当前 bindings 的镜像；正常选中后重开会产生虚假的旧选择，跳过状态也可能被降为 stale。只对 v0.1 执行旧字符串迁移，v0.2 依据 `skill_state` 恢复。

5. **P2：本地匹配对普通任务有可复现误报。** `src/promptsmith/skill_catalog.py:39-51,294-320` 用子串命中计分。关键工作“整理用户需求并撰写摄影社招新通知”被“需求”一词命中 `to-spec`，返回 `ok` 且 `selection_allowed=True`，尽管工作是 500 字微信群通知。现有测试只覆盖没有“需求”一词的近似通知。应加工作语境/类别约束和该近邻反例；没有合适项应返回 no_match，不能让弱词命中成为可选方法。

6. **P2：目录来源字段不完整，运行时没有核验原文。** `resources/skill_catalog/catalog_v0.1.json` 三条记录的 `repository`、`fixed_commit` 均为 null，但既有调研资料已记录仓库及固定提交。`src/promptsmith/ui.py:2519-2523` 以 `verify_sources=False` 加载，发行包只含目录摘要，候选状态 `catalog_recorded` 仍可选。摘要可作为有边界的候选，但当前数据不足以在交付中追溯固定来源；需补齐可核验来源字段，并清楚区分“目录记录”与“运行时核验原文”。

7. **P2：最终正文的可读渲染遗漏已确认关键工作信息。** `src/promptsmith/finalization.py:688-748` 的 canonical body 主要渲染目标、要求、步骤、交付物和标准，未把方案中的 `key_work`、requirement coverage 等完整结构呈现到导出正文。结构化 JSON 仍保留这些字段，但用户交给另一个 AI 的独立文本可能看不到关键工作分解。应补齐固定章节或明确这些字段如何映射到步骤，避免“结构齐备”只存在于内部 JSON。

8. **P2/P3：草稿导出和复核导航存在体验断点。** `src/promptsmith/exporter.py:23-30` 允许在尚未生成最终草稿时导出 `not_started`／“暂无正文”文件；UI 草稿导出入口未据此禁用。`src/promptsmith/ui.py:3374-3444` 把 M4 变化复核项导向通用方案页，未定位到变化的接受／拒绝控件。`ui.py:3184-3188` 始终以 `overwrite=False` 调用 exporter，现有文件即使经保存对话框选择也无法从 UI 覆盖。分别补状态门槛、定位和显式覆盖路径。
