# 冲突参与方完整性定点修复记录

日期：2026-09-23

## 范围与结论

本轮只修复一个状态漏洞：模型沿用未解决冲突编号，却遗漏或替换其中仍有效的正式需求参与方时，程序不再用缩减结果覆盖旧冲突，也不会让矛盾需求绕过确认门槛。

本轮为离线程序验证，使用合成模型响应，没有发起真实模型调用。历史验收目录 `acceptance_20260923_round4_review/` 未改写。

## 实现

- `src/promptsmith/m1.py`：在输出 Schema 校验之后，逐个比较请求中的旧冲突与模型返回。旧冲突中仍存在于当前正式需求列表的参与方必须全部保留；只有冲突编号相同、参与方数量不少于两个均不足以通过。
- `src/promptsmith/session.py`：在 `stage_m1_result()` 写入类别、候选、冲突和确认依据之前执行同一连续性校验，防止调用方绕过 M1 解析器造成部分覆盖。
- 合法恢复路径保持不变：用户实际编辑、替换或撤回需求时，程序先改写活动引用；真实撤回冲突一方后，冲突可关闭，重新分析后可以确认并保存。

## 指定场景

| 场景 | 实际结果 |
|---|---|
| 保留原冲突编号但漏掉一方 | 输入和输出 Schema 通过，语义校验拒绝；原冲突保留，确认被拦，保存重开正确 |
| 用另一条有效需求替换原参与方 | 即使返回仍有两个参与方，语义校验仍拒绝；原冲突和确认状态不变 |
| 完整保留原冲突参与方 | 正常解析并应用；冲突继续存在，确认继续被拦截 |
| 用户真实撤回矛盾一方 | 引用改写后冲突关闭；重新分析、确认和保存重开均通过 |
| C2 编辑顺序与整条冲突遗漏 | 编辑后冲突参与方按新需求编号保留；确认被拦；模型整条遗漏仍被拒绝 |
| 直接调用状态应用入口并缩减参与方 | 应用前拒绝；需求、冲突、分析依据、确认依据和类别建议均未被覆盖 |
