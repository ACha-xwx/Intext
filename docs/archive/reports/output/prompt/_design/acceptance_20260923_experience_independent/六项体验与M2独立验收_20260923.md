# 六项体验与 M2 独立验收

日期：2026-09-23。对象：当前源码与 `dist/PromptSmith.exe`，对应 20:09:49 构建。报告版本 v1.0。

## 结论

**本轮体验验收不通过，暂不建议按“六项建议与 M2 已整体完成”进入后续功能阶段。** 模型列表和主页面右键菜单已有实际实现，不能说六项都没做；但继续按钮行为、重复追问保护、编辑弹窗右键、布局可读性及 M2 编辑完整性仍有明确缺口。

本轮复跑现有测试：149 项通过，17.42 秒，退出码 0。随后独立探针复现了现有测试未覆盖的问题。测试通过与用户体验达标是不同结论。

协议只支持一种属于范围差异：此前合并提示 v0.2 明确把 Responses、Anthropic Messages 和多协议选择列为后续扩展。当前实现遵循了这一限制，但不满足用户最新提出的可选择协议期望。不能把它归咎为开发方漏做了旧提示中的必做要求；下一版执行提示需要明确调整范围。

## 需要先修复的具体问题

### P1-1：“继续分析回答”的文案与实际动作不一致

位置：`src/promptsmith/ui.py:595`、`:622`，尤其标签判断中的待评估回答分支与点击函数分支不一致。

独立复现通过正式 M1 输入构建、Schema、语义校验及状态应用建立：

1. 用户任务是写活动邀请邮件，受众未定；模型人工 fixture 提出交付物候选和受众问题。
2. 接受候选，回答“还不确定”。原话被记录为待评估，阻断缺口保留。
3. 下一次合法合成响应保留缺口但没有 gap_updates；程序按既有规则保留待评估回答，并把分析依据更新到当前需求版本。
4. 主按钮显示“继续分析回答”。通过真实 Tk Button.invoke 连续触发两次。
5. 两次均走 confirm_requirements，弹出“仍有影响方向的未决项。”；start_analysis 调用数为 0，业务状态不变。

这是一种可复现的用户操作闭环，不是已证明的无限网络循环。现有完整 UI 测试直接调用 start_analysis，没有覆盖此状态下主按钮的真实路由。

修复验收：主动作文字、可用性和实际处理器来自同一状态决策；待评估回答进入分析，方向阻断进入补充/编辑路径，不能继续引导必然失败的确认。测试必须调用真实按钮/主入口，不能只绕过它调用底层分析函数。

### P1-2：已解决的问题可用新缺口 ID 重新接收

位置：`src/promptsmith/m1.py:350` 附近。新增的重复保护检查 pending 回答及 skipped/unsure 历史，没有覆盖已经 applied/resolved 的回答。

独立复现：同一个受众问题得到明确回答“发给大一新生”，通过合法 gap_updates 标为 resolved 后，缺口确实清除；没有新增用户信息，再返回相同 field、scope、问题原文但新的 gap_id/question_id，Schema、语义和状态应用均接受。

本例甚至不需要判断换措辞是否语义相同。当前证据证明程序保护可被新 ID 绕过，不证明真实模型每次都会产生这种响应。

修复验收：已解决历史继续参与去重；同范围同缺口无新依据不得重问，换 ID 无法绕过。必要细化、不同子任务及用户明确重开仍需可行，不能用仅 field 相同就全面封锁的方式修复。

### P1-3：M2 核心步骤内容无法完整编辑，空步骤也可确认

位置：`src/promptsmith/ui.py:1018`、`src/promptsmith/session.py:757`、`:782`，及 M2 输出契约/方案本地验证。

当前编辑步骤只修改 title、purpose。inputs、actions、outputs、completion_criteria、依赖及需求关联没有对应的步骤编辑入口。新增步骤将这些字段全部设为空数组。

独立复现：从合法 M2 fixture 经正式解析和应用生成方案 → 新增“补充审阅”步骤，只填标题和目的 → 完成现有关键工作复核 → 确认方案 → 保存重开。新步骤的行动、输出、完成标准仍为空，重开后方案状态仍为 confirmed。

这不符合“用户编辑并确认完整方案”的目标。已实现的增加/删除/重排按钮不能代替完整步骤编辑和确认前内容检查。

修复验收：实际步骤内容可查看和编辑；新增步骤在行动、输出、可核对完成标准等必要内容未完成时只能作为草稿，不能直接确认。输入确实不需要某项时允许有明确语义，不应盲目为所有可选数组设最小一项。编辑引用应可修订并验证；不能只拦删除却不给用户维护依赖与引用的路径。

### P2-1：右键菜单没有覆盖真正用于编辑的弹窗

位置：`src/promptsmith/ui.py:333`、`:433`、`:535`、`:835`、`:968`、`:1006`、`:1029`、`:1109`。

主页面只给指定 Text/Entry 绑定菜单。需求编辑、步骤编辑和多个方案栏目通过 simpledialog.askstring 创建新 Entry，这些控件没有复用绑定。

本轮对真实“编辑需求”弹窗生成右键事件：实例绑定 false、类绑定 false、菜单新增数 0。主页面任务框实际鼠标右键菜单则能弹出。因此结论为“局部完成，常用编辑路径漏接”，不是完全无菜单。

需求、候选、问题和步骤的 Treeview 也没有右键复制所选记录的绑定。可作为同一修整项补齐合理的只读复制；不应给只读列表添加粘贴等修改动作。

修复验收：逐个走需求/方案编辑窗口，不只测试 capabilities 辅助函数；验证中文选区、实际复制粘贴、只读限制和快捷键，使用可复用控件绑定。

### P2-2：布局检查没有检查控件内部，字号改善不足

位置：`src/promptsmith/ui.py:125`、`:228`、`:269`、`:289`、`:436`；旧检查在 `scripts/verify_ui_layout.py`。

本轮读取真实字体配置：TLabel、TButton、详情 9 pt，任务 10 pt。发行窗口可见多个同权重按钮、空表格和大片空白；任务输入仅两行高。是否“更大气”需要视觉判断，但以下裁切是客观问题。

独立源程序在 1120×780、当前 Tk 缩放下：

| 控件 | 实际宽度 | 列宽总和 | 横向可见比例 | 横向滚动条 |
|---|---:|---:|---:|---|
| 需求表 | 504 px | 550 px | 91.3% | 无 |
| 候选表 | 504 px | 540 px | 93.0% | 无 |
| 方案步骤表 | 540 px | 595 px | 90.4% | 无 |

本轮发行窗口截图中需求“状态”表头已部分裁切。旧脚本只检查选定控件的矩形位于根窗口内且宽高大于最低值，没有检查列宽、文字完整性、按钮遮挡和阅读体验；因此旧“几何通过”不能用于否定用户反馈。

修复验收：统一正文与控件字号层级；让输入和当前重点内容有足够面积，空态简明说明下一步；调整表格列伸缩并提供必要滚动。新会话、长任务、多条需求、M2 长方案均实际查看。125%/150% 的真实 Windows 缩放仍需另验，Tk scaling 模拟不能冒充系统 DPI 验收。

### P2-3：空态与问题处理引导仍不明确

位置：`src/promptsmith/ui.py:595`、`:622`、`:1140`、`:1367`。

空任务状态的主按钮正常可点，下一步显示“开始或继续分析当前任务”，没有先指出要输入任务。回答后还提示点击旧名称“分析 / 继续”，与实际动态按钮不一致。“回答问题”“核对候选”等主动作通常只移动焦点，没有自动定位具体待处理项；回答函数随后仍要求先选中问题。

修复验收：状态不满足时显示对应前置条件；主动作能把用户带到具体待处理项，明确需要哪一步，而不是仅换文案或焦点。保留必要的自由编辑与返回入口，避免把状态管理术语当作主要用户说明。

### P3：模型目录对配置来回切换的过期保护不完整

位置：`src/promptsmith/ui.py:499`、`:515`。

目前回调只比较供应商、地址和 key 的值快照；程序已经有 connection_version，但模型目录回调未用它。独立探针在请求快照 A 后切至 B，再切回 A，connection_version 增加，但旧 A 响应仍写入列表。普通 A→B 的迟到拒收测试通过，A→B→A 没有覆盖。

这是低优先级边界问题，不应掩盖模型列表正常路径已经实现。修复时按请求身份及相关配置世代判定结果归属，并继续保留用户手填模型 ID。

## 协议选择：应调整下一轮范围，而非伪装修复

当前 API 层 `src/promptsmith/api.py:12`、`:40` 把 provider/protocol 限为 DeepSeek 与 OpenAI Chat Completions；UI `:199`–`:202` 是固定文字。

用户早先原话为“建议以后可以支持多种协议”，先前融合提示据此把多协议实际适配和选择器排除在本轮。用户本次明确指出不能选择，下一轮必须以这次期望重新定范围。不能加一个可选 Responses/Anthropic 的下拉框但仍发 Chat Completions 请求，也不能把未实现选项描述为可用。

本轮只做验收，不自行实现协议适配。真正支持哪些协议、每种协议的请求与响应/模型目录差异，应在下一份开发提示中具体落地并验证。
