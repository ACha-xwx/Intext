# M2 初始方案实现与验证报告

日期：2026-09-23。证据类型：离线程序验证、HTTP stub、自动化 UI 路径、源码与发行烟测。**本轮没有真实模型调用。**

## 实现结果

- M1 继续使用 `M1_system_v0.5`／`m1.v0.2`；M2 新增并接入 `M2_system_v0.1`／`m2.v0.1`。
- M2 只读取当前已确认需求快照。候选、开放冲突、需求待复核、方向性未知、确认版本过期或引用异常时，在调用前阻止。
- 正常输出必须逐项覆盖全部正式需求、逐项保留可延后未知，并通过稳定 ID、交叉引用、重复 ID 和步骤／关键工作循环依赖检查。`status=error`、非法或迟到返回不覆盖旧方案。
- 合法结果只成为方案草稿。程序维护 `plan_id`、`plan_version`、来源需求版本、确认版本、修改标记、来源快照、关键工作复核和归档。
- 第二页已开放，支持编辑目标、受众、范围、步骤、交付物、完成标准、未决事项、系统建议和关键工作；步骤支持新增、删除、上移和下移。用户不需要手写 JSON。
- 普通方案编辑不改变需求版本；实际修改任务、类别或需求会保留旧方案并标记 `stale`。重新确认后生成新方案，旧方案进入 `plan_archive`。
- 草稿、修改、关键工作复核、方案确认、来源快照、未知和归档随 JSON 保存重开；旧 M1 会话补齐默认方案，未知未来会话格式拒绝。

## 六条体验／API 修整

1. 供应商 DeepSeek 与 OpenAI Chat Completions 兼容协议分开显示；旧协议 ID 兼容加载。
2. 模型目录使用当前地址和运行时密钥，支持手填模型；正常、空列表、401／403、404、超时、网络和格式错误均有程序检查。
3. M1、M2 的常见文本控件复用剪切、复制、粘贴、全选和可用时撤销。
4. 主动作按冲突、问题、候选、复核、需求确认、方案生成／复核／查看状态变化。
5. M1 增加同缺口同字段／范围的新 ID 重问保护和成功但无业务进展提示；请求目的及连接快照隔离 M1、M2 和模型目录回调。
6. 1120×780 的当前 Tk 缩放、模拟 125% 和模拟 150% 三档几何检查通过；这不是修改 Windows 系统 DPI 后的人工截图验收。
