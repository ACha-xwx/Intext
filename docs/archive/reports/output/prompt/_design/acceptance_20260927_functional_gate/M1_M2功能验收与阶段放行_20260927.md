## 独立流程及可复核证据

案例一：本地任务清单工具，不得联网，用途通过追问明确为课堂演示，参考材料保留为未知。
案例二：社团招新通知，不得编造活动日期，受众通过追问明确为大一新生，参考材料保留为未知。

两例从新建会话开始，未直接构造已确认状态：

任务输入 → M1 候选与问题 → 用户接受 → 方向未知时确认被拒绝 → 用户回答 → 合法评估只关闭目标缺口 → 用户确认需求 → 无 Skill 的完整 M2 草稿 → 关键工作复核 → 用户确认方案 → 保存重开 → 步骤编辑与再次复核确认 → 拒收迟到方案和遗漏未知的方案 → 修改需求、旧方案保留为 stale → 保存重开 stale 状态 → 再次分析确认 → 重生成并归档旧方案 → 再次保存重开。

两例也分别验证：即使关键工作已复核，步骤行动、输出和完成标准为空时仍不能确认。

生产 workflow、解析/校验、会话状态和存储代码按原样运行；验收脚本替代 completion client 和证据记录器，以保证人工响应不会被标记为真实模型调用。两例不经过外部网络。本轮既有测试另外覆盖本地 HTTP stub 与真实协议适配代码的连接。

本目录证据：
- pytest_full.xml：完整现有测试结果。
- functional_flow_results.json：两条独立流程的全部断言与结果。
- offline_fixtures/：人工输入/响应与检查记录，标为 manual_fixture、real_model_call=false。
- coding_*_session.json、writing_*_session.json：确认、过期、重新生成后的会话快照。
- release_check.json：全部源码模块和提示资源的发行一致性检查。
- smoke_and_test_summary.json：启动烟测、测试时间及各模块计数。
- check_functional_flow.py、check_release.py：可复核脚本，输出使用排他创建以保护历史证据。
