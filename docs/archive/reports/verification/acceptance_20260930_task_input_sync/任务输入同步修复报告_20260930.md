# 任务输入按钮状态同步修复

日期：2026-09-30。范围仅为任务输入与主按钮状态同步；Skill、协议适配、布局、SessionState 和模型提示未改。

## 根因与修复

任务框是 `tk.Text`，输入时不会自动更新 `session.task_text`。原主按钮先以会话中的空任务判为 `focus_task`，因此无法到达后续 `start_analysis()` 中的 `_sync_input()`。按钮只聚焦已经有文字的输入框，用户看不到分析或错误提示。修复前已实际复现“讲一下JGS”输入后标签错误、主操作不调用分析、按钮首击未同步三种断言失败，见 [pytest_before.txt](<../../../README.md>)。该文件也包含早期测试 fixture 的问题，不把其中所有失败都当成产品缺陷。

修复集中在 `src/promptsmith/ui.py`：

1. `_visible_task_text()` 只读当前任务框。`_primary_action()` 在非 busy 时先处理可见空文本；非空时继续按原冲突、问题、候选、需求复核、方案和最终交付顺序判断。
2. `<<Modified>>` 覆盖键盘、粘贴、剪切、删除、撤销及程序填入文字；事件检查并清除修改标志，只刷新按钮，不调用 `set_task()`、不重建表格或清空选中项。模型连接字段变化也仅补充刷新按钮，协议逻辑不改。
3. `run_primary_action()` 对非空任务先 `_sync_input()`，正式同步任务和类别，再重新判定并执行原有动作；仅当需求版本改变时完整刷新。分析仍通过 `start_analysis()` 和既有 workflow／SessionState 校验。
4. 空文本不调用 `_sync_input()` 或 `set_task("")`，按钮显示“先输入任务”，点击只聚焦输入框、无请求。未修改 `_sync_input()` 本身，保留在途结果遇输入改变或清空时的既有校验。
5. 旧任务编辑沿用 `set_task()` 的来源、待复核、版本与下游失效规则；同文重复点击不增版本。未修改文本的待回答问题仍显示“回答问题”。

新增 `tests/test_task_input_sync.py` 共 10 个参数化测试实例，覆盖可见任务只读判断、同步时点、真实按钮进入分析提交、空任务（含旧任务仍在会话中）、键盘、右键粘贴、Ctrl+V、Ctrl+A/X/Z、清空、连接配置标签、新建与打开会话、旧任务修改和重复点击。

既有主流程测试保持原断言；只给此前仅注入内存 SessionState 的 fixture 补入对应任务框文字，模拟真实“打开会话”状态。没有删除测试或放宽 workflow／Schema 校验。
