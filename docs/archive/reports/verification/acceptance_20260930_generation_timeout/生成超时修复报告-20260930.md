# 生成超时与显式重试修复记录

日期：2026-09-30，Asia/Shanghai。本轮仅处理生成请求超时、输出上限、失败提示及重试恢复，不改 M1 提示、Schema、版本或需求状态规则。旧验收证据原样保留。

## 原因与修改

原 `src/promptsmith/api.py` 的 `ApiConfig.timeout_seconds` 默认值及 `src/promptsmith/ui.py` 的 `_api_config()` 都使用 45 秒。用户提供的第二轮证据显示等待约 45 秒后超时、raw 为空、Schema/语义校验未开始，因此不是回答格式或需求校验失败。

生成配置现在默认 **120 秒**；界面的模型列表和连接测试独立使用 **15 秒**。`ApiConfig` 仍支持调用方显式设置超时，本轮没有新增界面配置项。底层继续使用 urllib 的 socket 超时，并非整个操作严格在第 120 秒终止的总时限。

| 结构化生成协议 | 输出限制 |
|---|---|
| Chat Completions | `max_tokens=8192` |
| OpenAI Responses | `max_output_tokens=8192` |
| Anthropic Messages | `max_tokens=8192` |

M1—M5 的请求记录包含实际超时配置及对应 token 字段。超时仍记为 `timeout`，保留可得 latency；没有用量则记 `null`。未新增自动重试，未把超时转换为成功或 `input_error`；鉴权失败、错误响应和截断响应仍走原校验路径。

界面失败提示使用发起请求时捕获的模块和超时值，例如“需求分析等待超过120秒，已有回答和需求已保留，可检查网络、调整模型后点击重试”。M3/M4 同时覆盖 invoke 异常和返回失败 outcome 后 apply 抛错的路径。已有 workflow 负责失败记录与请求清理，UI 负责解除 busy、恢复操作入口；没有用提示规则替代程序状态约束。
