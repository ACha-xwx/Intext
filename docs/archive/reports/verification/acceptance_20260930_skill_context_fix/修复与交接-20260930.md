## 结果与修改

1. `SkillCatalog.match()` 和 `match_catalog()` 增加可选 `context_text`。只有目录明确设置 `allow_task_context: true` 的组可使用任务上下文；规格工作必须在关键工作自身字段出现。UI 与固定 D1/D2 runner 均传当前会话任务文本，保留先确认初始方案的流程。
2. `to-spec` 改用“报名工具／软件开发／应用程序”等复合软件语境词，去除“应用／网站／程序”等宽泛门槛。“范围边界”降为加分词，不能单独满足规格工作组，避免软件项目里的活动通知被误推荐。`domain-modeling`、`goal-prompt` 记录未改。
3. 匹配结果新增 `matched_sources`，理由明确标注“任务描述／关键工作”的词语来源；旧式 `work_signals` 目录也保留完整匹配理由。该字段属于本地候选证据，不改变模型 Schema 或会话格式。
4. `PromptSmith.spec` 补入显式 `M1Assets.load(legacy=True)` 所需的 `M1_system_v0.3.txt`、`M1_input.schema.json`、`M1_output.schema.json`。默认仍使用 M1 v0.8；不把“补齐旧加载器资源”写成“所有旧会话均走 legacy”。现有动态状态栏版本显示一并进入新包。
5. README、开发交接、提示设计索引及 CHANGELOG 指向本次证据；旧报告的数字保留为历史快照，修复设计索引中到根目录 verification 的相对路径。
